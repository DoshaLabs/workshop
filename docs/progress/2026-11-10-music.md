# The `music` permission

10 Nov 2026. One agent's round, after Colin's decision that the Spotify tile is built the
author's way, sandboxed, with no backend (ground rule 9: the contract grows for every author).
This round builds the permission and its documentation, not a Spotify tile; Colin builds that
with "make one with Claude". `npm run typecheck` clean. `npm test`: 292 passed (28 files; 27 new
in `test/music.test.ts`, plus new cases in manifest and permissions). `npm run smoke`: 295 passed,
0 failed (15 new under `music:`).

## What a tile gets

`"permissions": { "music": true }` with `"workshop": "^1.3"`. `workshop.music` exists only on a
tile that declares it (like `workshop.backend`; the probe checks it is absent):

```ts
workshop.music.get()          // → { player: 'spotify' | 'music' | null, state: 'playing' | 'paused' | 'stopped',
                              //     track: { title, artist, album, durationMs, art } | null,
                              //     positionMs, volume: 0–100 | null, shuffle?, repeat?: 'off' | 'one' | 'all',
                              //     error?: 'denied' | 'failed', message? }
workshop.music.watch(fn)      // → stop(); fires at once (if core has a reading) and on every change
workshop.music.play() / pause() / toggle() / next() / previous()
workshop.music.seek(ms)       // whole ms, 0 to 24 h
workshop.music.setVolume(v)   // whole number 0–100: the app's own volume
workshop.music.playUri(uri)   // Spotify only, spotify:(track|album|playlist|artist|episode|show):<22 base-62>
```

`art` is `tile://<id>/~music/art/<32 hex>` on the asking tile's own origin, or null until core has
the picture (the watcher fires again when it lands). The tile needs no `net` and only
`img-src 'self'`.

## What was built, file by file

- `src/shared/music.ts` (new): the state's types, the op list, `MUSIC_ART_PREFIX`, `ART_KEY_RE`,
  and the input rules (`badSeek`, `badVolume`, `badUri`, `SPOTIFY_URI_RE`), shared so the page's
  early error and main's check are the same rule.
- `src/main/music.ts` (new, no electron import): `MusicHost` and everything pure around it.
  - Four FIXED scripts in `SCRIPTS`, run as `/usr/bin/osascript -l <lang> -e <script> <argv…>`
    through `execFile` (no shell), 8 s timeout. A tile's value never enters a script's text: the
    player, op and one value go in as argv after `controlArgs` has checked them (closed op list,
    whole-number ranges, the URI regex, URI only to Spotify). The control script re-checks its
    numbers and the URI shape itself.
  - The poll and the controls are JavaScript for Automation, because JXA resolves an app's terms
    when it runs, so one script names both apps whether or not each is installed (an AppleScript
    `tell application "Spotify"` fails to compile on a Mac without Spotify, which would also
    break reading Music), and it prints JSON. One osascript call per poll reads both apps.
  - **Never launches an app.** Every script asks `Application(id).running()` (AppleScript:
    `application id "…" is running`) before sending anything; that is answered by Launch Services
    and sends no Apple event. A control with neither app open is refused in main before any
    script runs, with "workshop never opens them for you". Verified by hand: the scripts ran with
    Music closed and Music stayed closed.
  - Choosing the app (`choosePlayer`): the one playing, else one paused on a track, else one
    running; a tie keeps last time's choice (two paused apps do not swap), then Spotify. An app
    that refuses is still chosen, so the tile can say why.
  - Polling (`nextDelay`): none with no watcher; 1 s while playing; 3 s paused; 5 s stopped, none
    open, or a failed read; 15 s when macOS refused. 250 ms after a control. `get()` without a
    watcher reads once and answers from a reading under 800 ms old, so a page calling it in a loop
    costs at most about one osascript a second. One read at a time (`inflight`). Controls run one
    at a time; more than four queued are refused.
  - Artwork: keyed by a sha256 of player and track (`artKeyOf`), 16 kept in memory. Spotify: the
    `artworkUrl` from Spotify.app is fetched by main only if it is https on `*.scdn.co` or
    `*.spotifycdn.com`, no port, no credentials, no redirects, 5 s, 2 MB, and kept only if its
    bytes are a JPEG, PNG, WebP or GIF (`sniffImage`; served with that type and `nosniff`, so an
    SVG or HTML can never be served from a tile's origin this way). Music: the fourth script
    (AppleScript, since JXA cannot hand back raw picture data) writes `raw data of artwork 1 of
    current track` to a file in a folder main made with `mkdtemp`, named by main and passed as
    argv; main reads it, sniffs it and deletes it.
  - Errors: an Apple event error -1743 (`errAEEventNotPermitted`) is `error: 'denied'` with a
    message naming System Settings › Privacy & Security › Automation; controls then reject with
    the same words without trying. Any other failure (a timeout, garbage output, osascript
    missing) is `error: 'failed'` with the reason; the poll carries on.
- `src/main/music-bridge.ts` (new): the ipc side. `ws:tile:music-get`, `music-control` (invoke)
  and `music-watch` (send, true or false) are answered only for a page core attached, its top
  frame, its own origin (`guestOf` from index.ts) and a manifest with `music`. Watchers are by
  webContents; a page that reloads (its hello) or is destroyed stops watching. A new watcher is
  sent the last reading at once. Each tile is sent the state with the art URL on its own origin
  (`forTile`).
- `src/main/tiles.ts`: the `tile://` handler serves `/~music/art/<key>` from the host's memory,
  only for a tile with `music` and a key of 32 hex; 404 otherwise.
- `src/preload/tile.ts`: `workshop.music`, present only with the permission; early errors from the
  shared rules; one `music-watch true` when the first watcher subscribes and `false` when the
  last stops.
- `src/shared/manifest.ts`: `music` is a known boolean permission; `BRIDGE_VERSION` is `1.3.0`.
- `src/shared/permissions.ts`: "see and control what Spotify or Music is playing"; `music` is a
  key, so an update that adds it asks again.
- `src/shared/ipc.ts`: four channels. `src/main/index.ts`: about ten lines (imports, the host made
  after `bridge()`, the hello forgets a reloaded page's watch, stop on quit and after smoke).
- `template/CLAUDE.md`: the permission row, the API, a ten-line now-playing example and the
  rules a tile author needs (never opens an app, the consent prompt and what denial looks like,
  poll pace and interpolating position, art on its own origin, the URI form, no search or
  playlist listing, shuffle and repeat read-only). The trusted-tier paragraph no longer names
  Spotify.
- Tests: `test/music.test.ts` (parsing the real poll output captured on this Mac, Music's units,
  odd and hostile output, choosing the app, the denied and failed states, art URLs per tile,
  poll pacing, the input rules and URI forms including injection attempts, argv building,
  control output, the art host allowlist and byte sniffing, and `MusicHost` on a fake runner and a
  hand-driven clock: polls only while watched, freshness, one read at a time, art landing,
  Music's art through a file that is removed, controls as argv, never opening an app, denial,
  a failing poll, no change no message). Manifest and permissions cases.
- Smoke: `src/main/smoke-music.ts` hands `MusicHost` a stand-in runner and art fetcher in every
  smoke run (`index.ts`, `SMOKE`), so smoke never touches the real apps. `test/fixtures/music`
  (id `music-probe`) is loaded as a dev tile and driven from its page: the probe has no
  `workshop.music` and gets 404 for the art path; the music tile reads state, gets art on its own
  origin and loads it with no `net`; watching polls about once a second and stops with the last
  watcher; pause reaches the runner and the watcher hears it; seek, volume and a URI reach the
  runner as checked argv; bad values are refused in the page and, called on the host directly,
  in main before the runner; denied and nothing-open are states, and controls say why.

## Decisions

- **`playUri` is in**, Spotify only, the 22-character base-62 share form for track, album,
  playlist, artist, episode and show. Why: a tile cannot search Spotify without its web API (an
  account key, `net`), so without it a Spotify tile could never start anything but what is
  already queued; with it, a tile can keep favourites the user pastes. The risk is small: it only
  plays something in the user's own Spotify, the value goes in as argv, is checked twice, and the
  legacy `spotify:user:…` and `spotify:local:…` forms are refused because they carry free text.
  Music.app has no equivalent that is not a free-form search, so it gets none.
- **JXA, not AppleScript, for the poll and controls** (above). The art script is AppleScript.
- **Not in v1**: setting shuffle or repeat, playlists, search, liked songs, Music's library. Each
  is easy to add as another fixed op if a tile wants it.
- **`workshop.music` is absent without the permission**, like `backend`, rather than present and
  rejecting like `storage`. The task asked for it; it also keeps a tile from guessing whether the
  user has a player.
- **The art is per tile origin, the cache is global.** Two music tiles share one fetch.
- **Polling keeps going while the window is hidden** if a page watches. A follow-up could pause it
  when the window is hidden or minimized (the knot clock already knows).

## macOS Automation consent: what was found, what is unverified

- The first Apple event core sends to Spotify (or Music) makes macOS ask "“X” wants access to
  control “Spotify”". The answer is kept per pair of apps in TCC; the user can change it in
  System Settings › Privacy & Security › Automation. A "no" makes every later event fail at once
  with -1743, which core shows as `error: 'denied'`. Nothing crashes: osascript exits non-zero
  or the JXA catch returns the number, and the host turns either into a state.
- No prompt happens until a tile with `music` is live and watching or calls `get()`, AND one of
  the apps is running (`running()` sends no event). A user who never adds a music tile is never
  asked.
- **Packaged build:** the app's Info.plist must carry `NSAppleEventsUsageDescription` (the
  sentence in the prompt), for example "workshop shows and controls what Spotify or Music is
  playing, for tiles you allow." Apple documents the key as required for sending Apple events;
  without it the event may be refused with no prompt at all (not tried here). If the app is signed with the hardened runtime it also needs the entitlement
  `com.apple.security.automation.apple-events`. There is no packaging config in the repo yet
  (no electron-builder or forge section), so neither is added; whoever adds packaging must.
- **Under `electron .` (npm run dev, smoke):** `node_modules/electron/dist/Electron.app`'s
  Info.plist has NO `NSAppleEventsUsageDescription` (checked). macOS attributes the event from
  the osascript child to the "responsible" app, which for a binary started from a terminal is
  usually the terminal (or the app hosting it), not Electron. So in development the prompt most
  likely names the terminal or the app the session runs in, and the grant is that app's.
  **Unverified**: on this Mac a hand-run poll from this session read Spotify with no prompt,
  so whichever app is responsible here was already allowed; I could not see which.
- Smoke never sends an Apple event (the stand-in runner), so it cannot trigger a prompt.

## Tried by hand on this Mac (read-only)

Spotify was running and playing; Music was closed. The poll script (the exact text in
`SCRIPTS.poll`) printed, in about 0.2 s:

```json
{"spotify":{"running":true,"state":"playing","volume":81,"shuffle":true,"repeat":"off","position":40.89,"track":{"title":"Umbrella Sky","artist":"DowtownRain","album":"Umbrella Sky","duration":117433,"id":"spotify:track:2Y4rRlanUi7BHYLBDTYELz","art":"https://i.scdn.co/image/ab67616d…"}},"music":{"running":false}}
```

So Spotify's duration is milliseconds and its position seconds, as the parser assumes (the unit
test uses this output). The control script was run only with an op it refuses (`spotify nope` →
`{"ok":false,"error":"op"}`) and against the closed Music (`music play` →
`{"ok":false,"error":"not-running"}`); Music did not open. The art script ran with Music closed,
printed `none` and did not open it. One artwork URL was fetched with node's fetch and
`redirect: 'error'`: 200, `image/jpeg`, 66 KB, JPEG magic bytes. Nothing was played, paused or
changed.

**Unverified**: Music.app's side end to end (its property names in JXA, `songRepeat`,
`persistentID`, the art script writing real artwork), because Music was not running and was not
opened. Spotify's setters (`playerPosition =`, `soundVolume =`, `playTrack`) and `playpause`,
`nextTrack`, `previousTrack` were not run, by instruction. They are the names in each app's
scripting dictionary; the first real tile will exercise them.

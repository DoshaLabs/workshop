app (`WORKSHOP_REAL_CLAUDE=1 npx electron . --smoke`, 82 passed).

- The Agent tool runs in the background by default now: its PostToolUse comes at once with
  `tool_response.isAsync: true, agentId, description`. The parent's Stop can fire while the
  subagent works; Stop carries `background_tasks: [{ id, type: 'subagent', status, description }]`.
- SubagentStart: `session_id` (the PARENT's), `transcript_path` (the parent's), `cwd`,
  `agent_id` (`a` + 16 hex), `agent_type`. No description.
- A subagent's PreToolUse and PostToolUse carry `agent_id` and `agent_type`. So the leash can
  tell a subagent's call from its session's.
- SubagentStop adds `agent_transcript_path` and `last_assistant_message`.
- The transcript: `<projects>/<cwd>/<session id>/subagents/agent-<id>.jsonl`, every line
  `isSidechain: true`, the first a user line with the brief and no `origin`. Beside it
  `agent-<id>.meta.json`: `agentType, isBuiltIn, description, toolUseId, spawnDepth,
  requestShape ('background'), pickedEffortModel, finished`.
- A PreToolUse `deny` answered for a subagent's call is honoured: the agent read the reason and
  returned at once, saying it was stopped. This is what kill rests on once the leash exists.
- The task notification comes back as a UserPromptSubmit whose prompt starts `<task-notification>`.
- `claude --bg` (helper sessions): inherits the environment of whoever ran it, honours
  `--settings`, `--name` and `--model`, IGNORES `--session-id` ("--bg manages the session id"),
  prints `backgrounded · <8 hex> · <name>`. Its hooks carry its own session id, which starts with
  those 8. `claude agents --json` lists it as `kind: background` with `state: 'done'` once its
  turn is over. `claude stop <id>` stops it and keeps the conversation.

## Subagents

`src/main/agents.ts` (carried from deck, without its betas and its own hold). Hooks reach it
through `core-sessions.ts` after the token and session id are checked.

- Nothing is guessed: `path` is null until the file is seen (under the parent transcript's folder,
  three folders deep, so `workflows/wf_<run>/` is found). The stop hook's path wins.
- A stop or a tool call for an agent never seen to start makes a tile only if its transcript
  exists (internal forks write none).
- No stop hook: finished when the sidecar says `finished: true` and the file has been still
  10 s. A later tool call of its takes that back.
- Names: the sidecar's `description`, else the brief's first line, else the type.
- Finished agents stay until the parent's next prompt you typed (not a task notification), 30
  minutes, 12 per parent, or ×.
- The tails: `TranscriptWatcher.syncAgents`, ids `agent:<id>`, sidechain lines accepted only there.

## Helper sessions

`src/main/helpers.ts`, `bin/workshop-helper.mjs`, skill `workshop:helper` in core's `plugin/`.
A session runs `node "$WORKSHOP_HELPER" start [--model m] [--name n] "<prompt>"`; core runs
`claude --bg` in the session's folder with our settings, every plugin dir, the parent's model
(unless asked) and ALWAYS the parent's permission mode, with `WORKSHOP_AUTH` pointing at the
helper's own token. Its first hook names its session id (must start with the printed 8 hex).
`list`, `result <id>`, `wait <id>`, `stop <id>`. At most 8 working per session. Kept in
`<profile>/helpers.json` so a restart still knows them. A session killed for good stops its
helpers; a parked one keeps them.

## The pack tile

`PackTile.tsx`: one tile per session with agents, right under the session's tile (or where it
would be while its terminal is in the center). One row tall, as every tile in that column, so the
columns still line up. Deck had one cell per alpha too; a tile per agent would push the sessions
off the screen with five agents. Head: the worker knot, the parent's name (click: its terminal),
"2 working · 1 done". A chip per agent. Under them the chosen one's line (kind and model or
phase, bg, the clock or ✓ time, pause when the leash is there, ■ kill in two clicks, ×) and its
conversation, ChatView unchanged. The newest working agent is chosen until you pick one.

The worker coat: with a sprite pack, `--mascot-sheet-worker` (already built). With the Knot,
`knotPalette(theme, mode, 'worker')` turns the accent and starting colours gold at their own
lightness (`goldOf`), still held to 3:1 on every theme (tested). `--ws-worker` is the same gold
for the tile's border and chosen chip.

## Kill, honestly

The CLI gives no other program a way to stop one of a session's subagents, and workshop never
wraps it. So kill on a subagent:

1. takes the tile at once and remembers the id for 6 hours, so its hooks never make a tile again;
2. types one line into the parent: `[workshop] The user stopped your subagent “x” (id …); if it
   is still running, stop it with TaskStop. No explanation needed…` (a background agent can then
   be stopped by its own session with TaskStop);
3. with the leash wired, refuses the held call and every later one with a PreToolUse deny, which
   the agent obeys (seen above).

Without the leash only 1 and 2 happen. A helper is killed with `claude stop <id>`, the CLI's own
command; its conversation is kept (`claude attach <id>`).

## Pause, and what the leash needs to do

`AgentTracker.preTool(rec, payload, gone)` is the seam. The leash's `/pretool` route should, for
every PreToolUse it receives:

- find the session by token (as `core-sessions.hook` does) and check `payload.session_id`;
- if `payload.agent_id` is set, answer with whatever `core.agents.preTool(rec, payload, gone)`
  resolves to (null: let it through; a decision: write it as the hook's stdout). `gone(cb)`
  should call `cb` when the CLI drops the request (its hook timeout), so the hold is let go;
- call `core.agents.setLeash(true)` once the PreToolUse hook is in the settings file. That shows
  the pause buttons and lets `pause` through;
- a helper's own calls come with the helper's token (`core.helpers.byToken`); `helpers.preTool`
  is a stub that lets everything through. Pause for a helper is refused today ("open it with
  claude attach").

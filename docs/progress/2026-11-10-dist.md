# The app icon, a packaged and signed workshop.app, and "Install update" (10 Nov 2026)

Colin: "Can we give it the knot as its logo, and have an option to run in dev mode (where the UI
updates instantly, especially as you develop tiles), otherwise you can 'install update' like we
have in deck when you are satisfied with your dev."

So workshop now runs two ways:

- **Dev**: `npm run dev`, profile `workshop-dev`. The window hot-reloads; dev tiles reload on save.
  The Dock shows the Knot.
- **Installed**: `/Applications/workshop.app`, profile `workshop`. Its top bar offers "Install
  update" when the repo it was built from has changed.

## What was built

### The icon (`npm run icon`, `scripts/icon.mjs`)

The cinquefoil drawn by the app's own `drawKnot` with Deep Space's working palette, recorded stroke
by stroke as `scripts/knot-svg.mjs` does and painted on a canvas in a hidden Electron window. The
tile is the macOS grid (an 824 px rounded square in 1024, a soft shadow, a faint starlight edge):
a dark indigo well, a violet and a blue haze, stars from 64 px up. The knot is centred on what is
drawn (the tilt throws it off its box's centre) and fills 0.78 of the tile.

- The pose: 1.5 loops into the cycle, where the five petals are even and the pulse rides over the
  top, chosen from a survey of 24 phases (`ICON_SHEET=<dir> npm run icon` writes that survey).
- The strand: above the app's 24 to 88 px it is scaled back as `site/main.ts` `large` does; at 32
  and 64 px it is thickened (1.35, 1.15), or it breaks into grey dots.
- **16 px does not read as a knot.** Nothing keeps five lobes apart in 13 pixels. A finer strand
  (0.8) keeps more of the holes, so what reads there is a violet and gold flower on the dark tile.
- Each size is drawn at its own size, not scaled down. Output: `build/icon.iconset/` (all ten
  files, 16 to 1024), `build/icon.icns` (`iconutil`), `build/icon.png` (1024, the dev Dock icon).

### Packaging (`npm run dist`)

`npm run build`, then `scripts/stamp.mjs` (writes `out/build-info.json`), then
`electron-builder --mac`, target `dir`: `dist/mac-arm64/workshop.app`, 331 MB, arm64 only.
`electron-builder` ^26.18.0 is a devDependency. The `build` block in `package.json`:

- `appId` `app.dosha.workshop`, `productName` `workshop`, copyright DoshaLabs.
- `files`: `out/**` only (plus the production node_modules electron-builder adds).
- `extraResources`: `tmux.conf`, `bin`, `tiles`, `template`, `assets`, `plugin`, `native`, and
  `out/check` (so `Resources/bin/workshop.mjs tile check` finds its rules beside it).
- `asarUnpack`: node-pty.
- `afterPack` (`scripts/after-pack.cjs`): takes Electron's generic Bluetooth and audio-capture
  requests out of Info.plist before signing. workshop uses neither.

**Core's own files** (`src/main/resources.ts`): from the repo they sit beside `package.json`
(`app.getAppPath()`); packaged, that path is inside `app.asar`, which tmux, `node`, `swiftc` and
the CLI's `--plugin-dir` cannot read. `coreFile(...)` (in `tiles.ts`) is the repo in dev and
`Contents/Resources` packaged. Every use moved to it: `tiles/` (registry and the builtin ids in
`tile-menu.ts`), `template/` (scaffold), `assets/fonts` (the tile fonts route), `native/` (the
recorder's Swift source), `plugin/`, and the sessions' `tmux.conf` and `bin/workshop-tile.mjs`
(`core-sessions.ts` `appPath`). Smoke's `test/fixtures` paths stay on `app.getAppPath()`: smoke runs
from the repo.

**Profiles**: `WORKSHOP_PROFILE=<name>` runs on a profile of that name (its own tmux socket, its
own folder in Application Support). It is how the packaged app was looked at without touching a
real profile, and how dev was checked here. Install update is off on a named profile.

### Signing

electron-builder found the one identity in the login keychain, an **Apple Development**
certificate, and signed with it (`type=distribution`, no provisioning profile). Hardened runtime on.
`codesign --verify --deep --strict` passes. **Not notarized** (no `notarize` options), so a copy
downloaded from elsewhere would meet Gatekeeper; built and run on this Mac it opens.

### Entitlements (`build/entitlements.mac.plist`)

| Entitlement | Why |
|---|---|
| `cs.allow-jit`, `cs.allow-unsigned-executable-memory` | V8 under the hardened runtime |
| `cs.disable-library-validation` | node-pty's native module |
| `device.audio-input` | the recorder (BlackHole and the microphone); tiles that declare `microphone` |
| `device.camera` | tiles that declare `camera` (tiles.ts grants `media` to those; Posture is planned) |
| `automation.apple-events` | `workshop.music` drives Music and Spotify through osascript |

Info.plist strings: `NSAppleEventsUsageDescription` (music), `NSMicrophoneUsageDescription`
(recorder, tiles allowed it), `NSCameraUsageDescription` (tiles allowed it). Screen capture has no
Info.plist string on macOS; the recorder's screen permission is asked by the system as before.

### Install update (`src/main/updates.ts`, `UpdateButton.tsx`)

Carried from deck's `main/updates.ts`, `scripts/stamp.mjs` and `scripts/lib/fingerprint.mjs`,
reviewed on the way:

- `out/build-info.json` (`{ repo, fingerprint, builtAt }`) ships in the asar. The packaged app on
  its usual profile reads it (`parseBuildInfo`, `src/shared/update.ts`); under `npm run dev`, in
  smoke, on a named profile, or for an app built without the stamp there is none, and nothing shows.
- The fingerprint hashes the working tree (uncommitted edits and new files too, `.gitignore`
  respected) of: `src`, `tiles`, `template`, `bin`, `plugin`, `native`, `assets`, `build`,
  `scripts/lib`, `scripts/stamp.mjs`, `tmux.conf`, `package.json`, `package-lock.json`,
  `electron.vite.config.ts`, `vite.tile-preload.config.ts`, `vite.check.config.ts` and the three
  tsconfigs. Not `docs`, `site`, `test`, the README or CLAUDE.md. It stages into a copy of the
  index, never the real one, and with `GIT_OPTIONAL_LOCKS=0`. A path the repo lacks is left out
  (git refuses a pathspec that matches nothing; deck's list always existed).
- Checked every minute and when the window comes forward. States: `none`, `available`, `building`,
  `installing`, `error` (kept until the source changes again). A click runs `npm run dist` in the
  repo with the user's shell environment, writing everything to `<profile>/update.log`; then a
  detached `/bin/sh` waits for the app's pid to go, `ditto`s the new bundle beside the old, swaps
  the two (the old removed only once the new is whole; if the copy fails it opens the old one
  again) and `open`s it. The app quits 300 ms after starting the swap. Refused: an app running
  from `dist/` itself.
- The button is the record button's size (`ghost small`), left of it: "Install update",
  "Building…", "Installing…", "Update failed" (the blocked colour, the reason in its tooltip, a
  click retries). The text never says "Claude". IPC: `CH.updateGet`, `updateInstall`,
  `updateState`, core's window only; `window.core.update` in the preload.

### First install (`npm run install-app`, `scripts/install-app.mjs`)

`npm run dist`, then the newest `dist/mac-*/workshop.app` copied to `/Applications/workshop.app`
(`ditto` beside, then swapped). It refuses while that app is running ("quit it first, or use its
own Install update"), and checks again after the build. `-- --no-build` installs what `dist/` holds;
`WORKSHOP_INSTALL_DIR=<dir>` installs elsewhere.

**Not run into /Applications here.** For the lead, with Colin's go-ahead:

```
cd ~/workshop && npm run install-app && open /Applications/workshop.app
```

## The dev experience, checked

On a throwaway profile (`WORKSHOP_PROFILE=workshop-devcheck npm run dev`), with screenshots:

- A CSS edit hot-swapped in place (`[vite] hmr update /src/styles.css`); the launcher kept its
  scroll position.
- A component edit (`RecordButton.tsx`'s label) went through React Fast Refresh, no reload.
- `node bin/workshop.mjs tile dev <folder>` handed a copy of the starter to the running app; an
  edit to its `dist/tile.js` showed in the tile on save.
- Nothing needed fixing. One gap left as it was: a change to `src/preload/tile.ts` still needs
  `npm run dev` again (the comment in `electron.vite.config.ts` says so). Tile authors never touch it.
- The Dock icon in dev is `app.dock.setIcon(build/icon.png)` when not packaged. The call runs; I
  did not take a picture of the Dock.

## Verified

- `npm run typecheck` clean; `npm test` 413 passed (35 files), 16 of them new in
  `test/updates.test.ts`: the fingerprint's paths, that it moves with source edits (uncommitted and
  untracked) and not with docs, README or CLAUDE.md, and leaves the real index alone; the
  build-info parse; the updater's states with a fake spawn (quiet, available, building, the swap's
  script and environment, quit after it, a failed build's last lines and log, no app found, npm
  missing, no second build); the bundle helpers; the resource paths in dev and packaged, and that
  every folder they name is an `extraResource`.
- `npm run smoke`: 359 passed, 0 failed (`smoke-dist.log`). The first run had one failure, "knot
  clock: reduced motion draws one still frame per knot (4 frames for 3 knots)": a frame landing
  between the count and the media change while another worktree's smoke ran on the same machine.
  Nothing here touches the Knot; the second run passed it.
- `npm run dist`: exit 0 in 130 s, signed, `codesign --verify --deep --strict` passes.
- The packaged app, opened with `open` (Finder's environment) on a throwaway profile: the window,
  Deep Space, the fonts and all three core tiles loaded, the Git tile's backend live from
  `Resources/tiles/git`. Quit cleanly; its profile removed.
- The swap script on real bundles: a copy of the signed app as the "installed" one, the build as
  the new, a sleeping process as the app that must quit, `open` shimmed: it waited for the pid,
  replaced the app, left no `.new` / `.old`, opened the right path, and the signature still verifies.
- `install-app --no-build` into a scratch folder, and its refusal while that copy was running.

## Not verified

- **The button end to end**: a click in an installed app, the build, the swap and the relaunch
  have not run as one; each part has. That sessions come back after it rests on the same path as
  any quit and relaunch (sessions are parked on quit and reattached at start), which smoke's
  restart check covers; the paths sessions hold (`Resources/bin`, `Resources/tmux.conf`) are the
  same after a swap.
- The microphone, camera and Apple Events prompts in the signed app (none was triggered).
- Notarization and an Intel or universal build: not attempted.

## node_modules

The worktree's `node_modules` is a link to `/Users/colin/workshop/node_modules`. `npm install
--save-dev electron-builder` run in the worktree replaced the link with a folder of its own, so it
was installed into the main checkout's node_modules with `npm install --prefix /Users/colin/workshop
--no-save --ignore-scripts electron-builder@26.18.0` (the main checkout's package.json and lock
untouched) and the link put back. This branch's `package.json` and `package-lock.json` carry the
devDependency; after merging, `npm install` in the main checkout agrees with what is there.
`npm run dist` runs `@electron/rebuild` for node-pty in that shared node_modules (same Electron).

## How the SVGs work

- **The real drawing.** `knot-svg.mjs` loads `src/shared/knot.ts` and `themes.ts` with Vite's
  `runnerImport` (no new dependency) and calls `drawKnot` with Deep Space's `work` palette into a
  context that records every stroke. Each stroke becomes a path; colour and width pairs are CSS
  classes; runs in the same class are merged; coordinates are one decimal and relative.
- **Seamless loop.** The frames cover exactly P loops (P = 2: 4.8 s at the working knot's 2.4 s a
  loop, 30 frames a loop). Checked: the strokes at phase 0 and at P × 2π are identical. Each frame
  is a `<g>` shown for 1/60 of the cycle by one `step-end` keyframe and a negative delay.
- **Reduced motion.** `@media (prefers-reduced-motion: reduce)` stops every animation and shows
  one frame, the phase the app holds still at (clock 1.1 loops, `Knot.tsx`). Checked in Electron
  with `--force-prefers-reduced-motion`: two captures 1.6 s apart are byte-identical.
- **The words.** GitHub shows a README's SVG through `<img>`, where no web font can load, so the
  banner's "workshop" (Nunito 800) and tagline (Nunito 600) are outlines, made by
  `scripts/wordmark.py` with fontTools and committed as `scripts/wordmark.json`.
- **One deliberate change from the app.** `drawKnot` makes the strand's width grow with the box,
  tuned for 24 to 88 px; at 240 to 560 px that is a fat tube. Above 120 px the generator and the
  site scale the width by `max(0.5, 120 / S + 0.35)`, the same rule in both
  (`site/main.ts` `large`, `knot-svg.mjs` `strokes`). Nothing in `knot.ts` changed for it.

## Regenerating

```sh
npm run readme-art                       # the three SVGs, from knot.ts and themes.ts as they are now
npm run site                             # the page, into out/site
npx vite --config vite.site.config.ts    # the page with reload, while working on it

# Only when the banner's words change (needs fontTools and brotli, nothing in package.json):
python3 -m venv /tmp/ft && /tmp/ft/bin/pip install fonttools brotli
/tmp/ft/bin/python scripts/wordmark.py && npm run readme-art

# The screenshots: a smoke run with WORKSHOP_SHOT_TILES=<png> and WORKSHOP_SHOT_GIT=<dir>, then
magick tiles.png -resize 1200x -dither FloydSteinberg -colors 256 PNG8:docs/assets/app.png
magick <dir>/pane-dark-window.png -crop 2000x1900+0+0 +repage -resize 1000x -dither FloydSteinberg -colors 256 PNG8:docs/assets/changes.png
```

A change to the Knot's maths or Deep Space's colours redraws the site on the next deploy (the
workflow watches those files), but the README's SVGs only when someone runs `npm run readme-art`
and commits them.

## The page

One page, `site/index.html`. The sky is `cosmos.ts` itself (`syncCosmos(COSMOS_ID)`), the hero is
the Knot drawn live from `knot.ts` at up to 560 px, and the Knot section shows all five modes
(working, needs you, starting, idle, ended) as buttons that flare when pressed, the way a call for
attention does. Content sits on see-through sheets like the app's panes. Fonts are the app's,
self-hosted from `assets/fonts/`. Reduced motion: the sky draws one frame (cosmos.ts's own rule)
and every knot holds still. Checked at 1280 and 390 px wide: no sideways scroll; code blocks
scroll inside themselves.

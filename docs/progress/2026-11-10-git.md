## What was built, file by file

- `tiles/git/tile.json`: built in, `"workshop": "^1.2"`, `pane: true`, `span: 2` (a line per
  worktree plus a few files needs the second row), `permissions`: `sessions: "read"` and
  `door: { ops: ["show"] }`; `backend: { entry: "backend.mjs", ops: ["changes", "diff"],
  timeoutMs: 20000 }`.
- `tiles/git/backend.mjs`: the two ops. The page names sessions by **id only**; the backend maps
  each to its folder from `sessions()` (core's list) and drops ids it does not know, so a page
  cannot point git at a path (smoke: a folder in place of an id gets "no such session" / nothing).
  A folder's worktree top (`rev-parse --show-toplevel`) is cached a minute; two polls of the same
  worktree at once share one read.
- `tiles/git/lib/git.mjs`: runs git. Every call: `spawn('git', [--no-pager, --no-optional-locks,
  -c core.quotepath=off, -c color.ui=false, -C <folder>, ...])` (an argv, no shell),
  `GIT_OPTIONAL_LOCKS=0`, `GIT_TERMINAL_PROMPT=0`, `LC_ALL=C`, git's repo-pointing variables
  (`GIT_DIR` and friends) removed, an 8 s timeout (SIGKILL), and a byte cap after which git is
  stopped and the answer says it was cut. Diffs add `--no-color --no-ext-diff --no-textconv
  --src-prefix=a/ --dst-prefix=b/ --submodule=short`, so the user's config (external diff tools,
  noprefix, colour) cannot change what is parsed. `changes(top)`: `status --porcelain=v2 -z
  --branch --untracked-files=all` (4 MB cap) plus `diff <base> --numstat -z -M`; `diff(top)`:
  the whole worktree's `diff <base>` (3 MB cap) plus each untracked file. `<base>` is HEAD, or the
  empty tree before the first commit.
- `tiles/git/lib/parse.mjs` (pure, tested as shipped): `parseStatus` (porcelain v2: branch, ahead
  / behind, ordinary / rename / conflict / untracked entries, submodules, a cut output's partial
  entry dropped), `parseNumstat`, `countLines`, `summarize`, `unquote` (C-quoted paths, octal
  UTF-8), `parseDiff` (files of hunks; a hunk is read by its line counts, so a removed line
  reading `--- x` stays a line; renames, copies, modes, binary; caps of 1,500 lines per file,
  8,000 per worktree and 2,000 characters per line, with `truncated` and `cutLines`),
  `untrackedDiff`, `parseWorktrees` / `dropWorktrees`, and `group`.
- `tiles/git/dist/` (the page, plain JS): `index.html` (strict CSP), `tile.css`, `tile.js`, and
  `model.js` (its rules, tested as shipped). Lines are drawn with `textContent` only; nothing
  from git is ever HTML.
- `tiles/git/plugin/`: skill `git:changes`, which runs `node "$WORKSHOP_TILE" git show`.
- `src/main/smoke-git.ts` (new) and one line in `smoke.ts`; `smoke-install.ts` now expects four
  built-in tiles on and two full-access rows (Trusted and Git).
- `test/git.test.ts` (parsing, plus real temp repos: a worktree, a staged rename, a deletion,
  untracked text, binary and a symlink, a repo with no commit, a held index lock, the cap) and
  `test/git-page.test.ts` (the page's rules; the two new theme colours' contrast).

## How Changes works

- **Which sessions**: the open ones (`workshop.sessions`, `open` and not dead). Parked sessions
  are left out.
- **Grouping**: by project (`root`, which every worktree of a repo shares), then by worktree top.
  **Sessions in one working tree share one line** naming all of them ("git-main and git-also ·
  one working tree"), with one status dot each; their changes cannot be told apart, so the tile
  does not pretend to. A session outside any repository is a muted line under its project.
- **A line**: branch (`main ↑2 ↓1`, `detached at 1a2b3c4`, `no commits yet`), `worktree <name>`
  when it is not the main tree, files touched, `+n −m`; "clean" when nothing changed.
- **How the count is made**: against HEAD, the index and the working tree together (`git diff
  HEAD --numstat -M`: staged and unstaged alike, a rename is one file). An untracked file counts
  all its lines as added (a last line without a newline counts), read for the first 200 untracked
  files of a worktree and up to 2 MB each; past either it is listed with no count. Binary (a NUL
  in the first 8,000 bytes, git's test) is listed with no count. A symlink counts as one line
  (its target's name), as git diffs it, and the file it points at is never read. Ignored files are
  not counted. Past 300 files the list stops and says how many more; past 4 MB of status output
  the count reads `n+ files`.
- **Another worktree inside the tree**: Claude's `.claude/worktrees/<name>` sits inside the main
  tree, and git lists it there as an untracked folder. When that folder is a worktree of the same
  repository (`git worktree list`), it is dropped from the main tree's line: it has its own.
- **Unfolding**: a click fetches that worktree's whole diff (`diff` op) and draws each file with
  its hunks, line numbers (both sides in the pane, the new side in the narrow tile), and a note
  where it was cut. Binary files say "Binary file, not shown". Each file can be folded. Unfolded
  worktrees are remembered (page localStorage).
- **Live**: a poll every 4 s while the Changes tab is up and `document.visibilityState` is
  `visible`, nothing otherwise; at once when a session opens, closes or changes status (a turn
  ending), which also refetches unfolded diffs (counts can stay the same while lines change). A
  poll that found nothing new redraws nothing. The head's badge is the number of changed files.
- **Door**: `show` (from a session) switches to Changes, unfolds the caller's worktree, opens the
  pane and answers `{ shown, branch, files, add, del }`.

## Not done, or not verified

- **Pictures**: `WORKSHOP_SHOT_GIT=<dir>` saves the pane in a dark and a light theme (checked:
  readable in both). The tile-view picture shows the column scrolled past the Git tile in a
  smoke run (many tiles), so the narrow view was not looked at; a capture of a page that is out
  of sight never settles, so each capture is given 3 s.

- **Visibility**: whether `document.visibilityState` turns `hidden` for a tile scrolled out of
  the column or a page hidden with CSS `visibility` was not measured. It does when the window is
  hidden or minimised. If it does not for a hidden webview, the tile polls (cheaply) while
  scrolled away; the fix is a contract change (core telling a page it is out of sight), not done.
- A real Claude session's edits (smoke uses fake-claude and writes the files itself).
- Very large repositories: the caps are there, the times were not measured. `git status` with
  `--untracked-files=all` in a tree with a huge unignored folder is the slow case; 8 s then an
  error on the line.
- `core.fsmonitor` and other config that runs programs during `git status` are the user's own and
  are left on (they speed up big repos).
- Each session's own changes inside a shared worktree are not separated (they cannot be from git).

## Next: Worktrees, History, PRs

- **Worktrees**: `git worktree list --porcelain -z` per project root (parsed already), each
  matched to the sessions whose top it is; ahead / behind main from `rev-list --left-right
  --count main...<branch>`; dirty from the same status read. The actions (open a session there,
  rebase, merge, remove) are the first writes: they need the two-click rule, a lock-aware runner
  (no `GIT_OPTIONAL_LOCKS` trick for writes: refuse while a session in that worktree is busy), and
  "new chat in a worktree" needs a way for a tile to start a session (a contract change:
  `sessions: "write"` only pastes today).
- **History**: `git log --all -z --format=...` with a cap; "which session made a commit" is the
  open question in plan.md. Cheapest honest answer: match by worktree and time (a commit on a
  branch whose worktree a session was in, between that session's start and end). A
  PostToolUse hook recording `git commit` per session would be exact but is core work.
- **PRs**: `gh pr list --json` / `gh pr checks` in each project root through the backend; the env
  allowlist has HOME, so gh's own login works; `GH_TOKEN` users would need it added (track B).

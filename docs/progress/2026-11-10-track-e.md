## What was built, file by file

### The preview pane

- `src/shared/preview.ts`: the pane's types, `PREVIEW_MAX` (2 MB), and `toggleTask(text, line,
  checked)`: flips the one mark on that line (bullets, numbers, nested, inside a quote, CRLF kept)
  and refuses a line that is no longer the task the pane saw.
- `src/shared/markdown.ts`: each task item now carries its source `line` (a quote's body is parsed
  with its offset), which is what a tick writes. Nothing else in the tree changed.
- `src/main/preview.ts`: `readDoc` (markdown, text, or `refused` with a plain note: folder,
  binary by sniffing, over 2 MB, missing), `writeDoc` and `tickTask` (only an unchanged, UTF-8,
  regular file; atomic temp + rename keeping the mode; a symlink is followed and stays a link),
  a `watchFile` on the one file shown (stat polling survives an editor's rename-over), and the
  `doc` call. Core's window only (`handle` checks the sender).
- `src/main/door.ts`: a new route, `POST /core/<name>`, answered (unlike `/hook/`), routed by
  token to `DoorHost.core`. `src/main/core-sessions.ts` accepts it only from a session's token
  (`byToken`); the door.json token from outside gets 400.
- `bin/workshop-doc.mjs`: `open <path> [--line N]` (and `path:N`), relative to the caller's cwd.
  Port from `$WORKSHOP_HOME/port`, token from the `$WORKSHOP_AUTH` file: never on a command line.
- `src/main/hooks.ts`: `WORKSHOP_DOC` in the `--settings` file's `env`, beside `WORKSHOP_TILE`.
  **Not `env.ts`**, as the brief said: `env.ts` is the login shell's environment; every
  workshop variable a session sees is set in the settings file, so it goes there.
- `plugin/` (new): core's own Claude Code plugin, name `workshop`, one skill `doc`
  (`workshop:doc`). `claude plugin validate plugin` passes. `index.ts` puts it first in
  `pluginDirs`, so every new session gets it with `--plugin-dir`.
- `src/renderer/src/preview-store.ts`: which file is shown, for the whole window; the
  unsaved-edits guard. `PreviewPane.tsx`: the pane (deck's DocPane without images, PDFs and
  folder walking). Markdown at reading size in the serif face; `source` shows it as written; code
  and text in mono with line numbers, the asked-for line marked; `edit` (any readable file), ⌘S,
  ● for unsaved. A change on disk is re-read at once: same text as the pane has (our own save
  racing the watcher) only moves the lock; otherwise it reloads, or with unsaved edits a bar says
  so and offers "reload" or "save mine over it". Every way out with unsaved edits (×, Esc, a new
  file, a session or tile taking the center) asks in a bar in the pane: save / discard / keep
  editing. No native `confirm()`.
- `Markdown.tsx`: optional `onPath` (references become links) and `onTask` (live checkboxes);
  `big` keeps headings at their size. `ChatView.tsx`: paths in prose, in your prompts and a tool
  line's file open in the pane, resolved against the session's folder (`cwd` is a new prop).
  `src/shared/paths.ts`: deck's `pathRefs` / `isPathRef` / `splitRef`, plus `linkPaths`.
- `App.tsx`: the pane takes the center while open, ahead of everything; closing returns to what
  was there (terminal, launcher, a tile's pane). Picking a session, ⌘1–9 / ⌘N, the launcher, a
  tile's pane, the mascot screen or a new focus close it.

### Drag to reorder

- `src/shared/order.ts`: `arrange` / `ordered` / `moved` / `pruned` (after deck's gridorder, one
  list per column). Keys not showing keep their place; unseen keys go to the foot.
- `src/shared/column.ts`: `order?` (tile instances) and `sessions?` (session ids), both left out
  until first saved, so existing columns and tests read as before.
- `src/renderer/src/reorder.ts`: `useReorder(column)`: a grip (⠿) on each head, a bar before or
  after the target, the + as "the foot", a drag type per column. While a drag is on the root has
  `ws-dragging` and `.tile-page` gets `pointer-events: none`: a webview takes every pointer
  event over it, drags included. (deck never needed this: its mini apps are React, not webviews.)
- `App.tsx`: the tile column drawn in the saved order; `SessionColumn.tsx`: grips on session
  tiles and the center line, a "most recent first" button while a manual order is on.

### Pictures in the prompt bar

- `src/main/drops.ts` (from deck's): a pasted picture (PNG, JPEG, GIF, WebP, up to 20 MB) is
  written 0600 to `<profile>/drops/` (pruned after 30 days); a Finder file keeps its own path;
  one in a temp folder (a screenshot thumbnail) is copied first. Preload's `keepDrop` gets a
  dropped file's path with `webUtils.getPathForFile` (Electron removed `File.path`).
- `SessionColumn.tsx` `TilePrompt`: paste into the bar, or drop a file anywhere on the tile; a
  chip with a thumbnail (a data: URL, which the window's CSP allows) and ×. On ⏎ each path goes
  in as its own bracketed paste, shell-escaped like Terminal.app does a drop, then the text, then ⏎.

## Decisions Colin should know about

1. **⌘1–9 and the session column.** Until you drag a session, nothing changes: the column is most
   recently active first and ⌘1–9 follow the order sessions were started. Once you drag one, the
   column keeps your order (activity no longer moves it) and ⌘1–9 follow the column top to
   bottom, so the badge and the position agree. A new session goes to the foot, so it takes the
   next number and never renumbers the others; parking one closes its gap, as before. "most
   recent first" at the column's foot drops your order. (Alternative not taken: keep ⌘ by start
   order always; then the top tile could wear ⌘3.) CLAUDE.md §7's "ordered by most recently
   active" is now the default rather than the rule.
2. **Which text becomes a link.** deck linked every reference in prose, which made "Node.js" a
   link to nowhere. Here: any reference in an inline code span; in running text only one with a
   slash (`src/x.ts`, `~/notes.md`); a tool line's file always.
3. **Core has a plugin now** (`plugin/` at the repo root, skill `workshop:doc`). It is the
   natural home for future core skills.
4. **`/core/<name>`** is a second answered route on the door's server, sessions only. The doc
   CLI does not work from a plain terminal (door.json's token is refused); easy to allow if wanted.
5. The pane shows text only. deck's image / PDF preview and folder walking were left out (the
   brief said refuse binaries). Images would need bytes over IPC and a `blob:` in the CSP.

## Not done, or not verified

- **Image paste with the real CLI is not verified.** The stand-in receives the path then the
  text; that Claude Code turns a pasted image path into an attached image is how a terminal drop
  works and what deck relies on, but no real turn was run with a picture.
- Drags in smoke are DOM events dispatched in the hidden window, not a pointer. That a real drag
  passes over a tile's webview rests on the computed `pointer-events: none`, which is checked;
  nobody has dragged by hand. No autoscroll while dragging past the column's edge (Chromium's
  own drag autoscroll may do it; not checked).
- A Finder drop onto a session tile is not in smoke (a real path cannot be faked); the pasted
  path is.
- The doc CLI does not raise or focus the window (it restores a minimized one only), so the
  pane may open behind another app.
- The pane's ⤢-style "whole window" mode from deck, and a "reveal in Finder / copy path" row,
  were not carried.

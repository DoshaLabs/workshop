## What was built, file by file

- `src/shared/permissions.ts` (new): a permission set in plain words (`permissionWords`, what can
  leave the machine first), as comparable keys (`permissionKeys`: a door's ops count, its timeout
  does not), and what changed between two (`permissionChange`, `needsAsking`).
- `src/shared/tile-index.ts` (new): the index's file format, `tiles.json`, an array of
  `{ id, name, author, hint, repo, commit, version, permissions, category }`. `checkEntry` /
  `checkIndex`: a bad entry is dropped with its reason, never the whole index; a repeated id is
  dropped; commit is 40 lowercase hex; repo is https only, unless the index itself is a local file
  (then file:// and absolute paths too); `permissions.backend` is refused; categories are a fixed
  list (`tools, notes, sessions, media, games, emulators, fun, other`, default `other`). The
  permissions are checked by `checkManifest` itself, around a stand-in manifest, so the index and
  tile.json can never disagree on what a permission is (and `manifest.ts` did not have to change).
- `src/shared/tile-menu.ts` (new): the types and IPC channel names between the menu and main
  (`MENU.*`), kept out of `ipc.ts` so this track touches it not at all.
- `src/main/tile-check.ts` (new): `checkTileFolder(folder, { dev, builtin })`. The manifest
  validator, `checkPlugin`, and what only the folder can tell: entry and icon exist and are inside
  the folder (real paths), no backend unless built in (a top-level `backend` as track B writes it,
  `permissions.backend` as v1 names it, or a `backend.mjs` file), and warnings for what loads but
  probably not as meant (no CSP meta, no icon, no repo, `.gitmodules`, symlinks, node_modules,
  over 50 MB). `formatCheck` for people. No electron imports.
- `vite.check.config.ts` (new) + `package.json` `build` and `dev`: tile-check.ts bundled with
  semver into `out/check/tile-check.mjs`, a plain node ES module. This is how the bin script
  reuses core's rules without copying them and without TypeScript on the user's side.
- `bin/workshop.mjs`: `workshop tile check <folder> [--json] [--dev]`, exit 0 / 1 (2 for usage or
  not built). `tile dev` unchanged.
- `template/CLAUDE.md`: a "Check it" section (`node "$(dirname "$WORKSHOP_TILE")/workshop.mjs"
  tile check .`, which needs no new env var), and "When you are done" now starts with running it.
- `src/main/install.ts` (new, no electron): `Installer` with `prepare` (fetch and check into a
  staging folder, return what the tile asks for), `confirm` (rename into `tiles/<id>`, replacing
  the old version), `cancel`, `remove`, `list`, `record`. The clone: `git init --template=` in an
  empty folder, then a depth-1 fetch of the one commit (falling back to fetching branches for a
  server that will not hand out a commit by id), checkout, `rev-parse` must equal the pin, then
  `.git` is deleted. Every git call runs with `core.hooksPath=/dev/null`, `core.symlinks=false`,
  submodules off, the LFS filter emptied plus `GIT_LFS_SKIP_SMUDGE=1`, `protocol.ext` never,
  `protocol.file` only for a local index, no prompts (`GIT_TERMINAL_PROMPT=0`, askpass false), no
  system config, a 2-minute timeout. What the user agreed to is kept beside the files in
  `.workshop-install.json` (repo, commit, version, permissions). Refusals, each a sentence: a
  backend; a built-in tile's id; an id loaded as a dev folder; an id already installed from another
  repo; a manifest id other than the index entry's; a permission the index entry did not list.
- `src/main/tile-menu.ts` (new): the IPC handlers (core's window only), the index reader
  (`WORKSHOP_INDEX` over `settings.index`; https with a 10 s timeout and a 2 MB cap, or a local
  file), registering an installed folder into the live registry (a new `rev`, so an update gets a
  fresh page), remove (unregisters; with "also delete what it stored": `tile-data/<id>`, main's
  cached store and grants, and every instance partition's web storage), and "load a folder"
  (`dialog.showOpenDialog`, then `addDevTile`, the same path as `workshop tile dev`). Built-in ids
  are read from `tiles/*/tile.json` themselves, so even a built-in tile that failed to load keeps
  its id. Leftover staging folders are deleted at start.
- `src/main/tiles.ts`: `readTile` refuses a backend for any source but `core`, with the reason
  (three lines plus an import), whatever the manifest validator says after track B.
- `src/main/settings.ts`: `index?: string` (https URL, `file:///…` or an absolute path; `''` clears).
- `src/main/index.ts`: one import and one line (`startTileMenu(...)` after `bridge()`).
- `src/preload/index.ts`: `window.core.menu.{state, setIndex, prepare, confirm, cancel, remove, loadFolder}`.
- `src/renderer/src/TilePicker.tsx`: rewritten as three tabs (the tab is remembered in the

- `src/renderer/src/styles.css`: a block at the end, "Track A".

  (new: a tile in a git repo made at runtime, shared by the smoke and `test/install.test.ts`).

## Not done, or not verified

- **"Load a folder" was never clicked**: the smoke cannot drive the macOS chooser. What it calls
  (`addDevTile`) is the tested path; the dialog itself is not.
- **No https fetch was exercised**: install and the index were driven only against local repos and
  a local file. The shallow fetch of one commit by id is what GitHub serves; on a server that
  refuses it the fallback fetches every branch, and a commit on no branch then fails to install.
- An index entry with a built-in tile's id shows "built in" and no Install button; an index entry
  for an id the user loads as a dev folder shows Install and then refuses with the reason.
- No "Install from a repo" in `bin/workshop.mjs` (`workshop tile install`); only the menu.
- No cap on a clone's size, and no check that a tile's install folder stays small; `tile check`
  only warns over 50 MB.
- The old `.picker-row` and `.picker-dev` rules in `styles.css` are now unused; left in place so
  as not to touch lines other tracks may be editing.
- The marketplace section is reached from the menu only; there is no badge or count anywhere
  saying an update is waiting.

## Decisions Colin should know about

- **An update asks again only when it ADDS something.** Dropping a permission goes in silently
  (and the prompt says "No longer: …" when it does ask). `sessions: write → read` counts as an
  addition of `read` and asks, which is harmless over-asking.
- **The index must list every permission the tile asks for.** A clone asking for more than its
  entry is refused, not shown: the index is what CI reviewed. Asking for less is fine.
- **Installed tiles live on the Marketplace tab** (under "Installed"), not on Yours, which is only
  folders loaded for development. A tile installed from a bare repo URL lands there too.
- **What install keeps**: `.workshop-install.json` inside the tile's folder (not served unless the
  entry is at the folder's root, and then only to the tile itself).
- **`tile check` needs a built workshop** (`out/check/`), as `tile dev` already needs `out/main/`.
  The index's CI will have to build workshop (or a later npm package of the checker). Inside a
  session, the template's command finds it next to `$WORKSHOP_TILE`.
- A local index (a file, or `WORKSHOP_INDEX`) may name local repos; an https index may not.
- Categories are a fixed list I picked; change `CATEGORIES` in `tile-index.ts` if wanted.

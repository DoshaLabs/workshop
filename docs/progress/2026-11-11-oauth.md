# Sign-in for tiles: `workshop.oauth` (bridge 1.5), 11 Nov 2026

Proposed by the Spotify tile (`~/workshop-tiles/spotify/docs/oauth-proposal.md`), reviewed and
built in core. This note is what was built and where it differs from the proposal.

## The problem

A desktop OAuth flow (RFC 8252) redirects the browser to a loopback address. A tile can run no
server, and its proxy refuses loopback, so nothing caught the redirect: the Spotify tile asked the
user to copy the dead page's address and paste it back.

## What core does

`workshop.oauth.authorize(url)` (main: `src/main/oauth.ts`, wired in `index.ts`, page side in
`preload/tile.ts`):

1. Needs real input in that page in the last 5 s, used up by the call (the overlay's gesture).
2. Checks the URL: https, no port or user name, host in `permissions.oauth`, `redirect_uri`
   exactly this tile's `redirectUri`, `response_type=code`, `code_challenge` with
   `code_challenge_method=S256`. A refusal opens nothing.
3. Replaces `state` with 32 random bytes of its own, keyed to the tile and the page that asked.
4. Binds 127.0.0.1:47800 if it is not already (an error says so if the port is taken), and opens
   the URL through `openForTile` (once a second per tile).
5. Answers only `GET /oauth/<id>/callback` with Host `127.0.0.1:47800` and a known state for that
   id; returns fixed pages (signed in / not completed / expired / not found) with a CSP of
   `default-src 'none'`, `no-store`, `no-referrer`. Resolves the page's promise with the query,
   `state` removed.
6. Lets the port go as soon as nothing is pending: after the callback, a timeout (5 min), a
   cancel, a newer `authorize()` from the same tile, or the page reloading or closing.

## Differences from the proposal

- **A redirect path per tile**, `/oauth/<id>/callback`, not one shared path. A public client has no
  secret, so the redirect URI registered with the provider is the only thing that binds a client
  id to an app. With one path for everyone, tile B could put tile A's client id in its URL, the
  user would approve A's consent screen, and B (holding its own PKCE verifier) would get the
  token. Core refuses a `redirect_uri` that is not the calling tile's own.
- **PKCE and the code flow are required**, so "core never holds a usable code" holds, and an
  implicit grant (token after `#`, which never reaches a server) fails at once instead of timing out.
- **One sign-in per input**, not just once a second.
- **The callback page says "not completed"** when the query has `error` or no `code`.
- **Smoke uses a free port**, never 47800, which the installed app may be using; the fixture
  reads `redirectUri` from the bridge.

## Which providers it serves

A provider works only if it (1) allows a loopback redirect, (2) lets a public client sign in with
PKCE and no secret, and (3) allows a cross-origin call to its token endpoint (the tile exchanges
the code with `fetch`). Spotify meets all three. GitHub (no CORS on the token endpoint, wants the
secret) and providers that require a secret (Notion, Strava, Todoist…) cannot be used from a
sandboxed tile at all. Others (Google, Dropbox, Linear, Microsoft) are unverified.

## Tests

- `test/oauth.test.ts`: the manifest (host rules, `^1.5`), words and keys, the URL check, and the
  host: query without state, a refused sign-in, state bound to its tile's path, Host and method
  checks, one per tile (a superseded call never closes the newer one's listener), page gone,
  timeout, port in use, browser not opened.
- `npm run smoke` (`smoke-oauth.ts`, `test/fixtures/oauth`): no workshop.oauth without the
  permission; refused without a click and on a second call from one click; a real click opens the
  URL with core's state; the tile's own page cannot reach the listener (its CSP allows it, core's
  proxy does not); another tile's path and another Host refused; the tile gets `code=…`; the
  listener is closed after; three bad URLs refused with nothing opened; cancel.

## For the Spotify tile

Set `"workshop": "^1.5"`, add `"oauth": ["accounts.spotify.com"]`, use
`workshop.oauth.redirectUri` and `authorize()` from the Connect button's click, keep the paste box
only when `workshop.oauth` is missing (an older core). Register
`http://127.0.0.1:47800/oauth/spotify/callback` on the shared app and in the bring-your-own-app steps.

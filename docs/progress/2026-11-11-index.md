### The check (`.github/workflows/check.yml`, `ci/check-index.mjs`, `ci/core.ts`)

It checks out DoshaLabs/workshop at main into `core/`, runs `npm ci --ignore-scripts` there (only
for semver and esbuild; none of workshop's scripts run), and bundles `ci/core.ts` with esbuild.
That file re-exports core's own `checkEntry`, `fetchCommit`, `checkTileFolder`, `permissionWords`,
`permissionChange` and `BRIDGE_VERSION`. Chosen over building `out/check/tile-check.mjs` because
the check also needs the installer's fetch and the index rules, which that bundle does not hold,
and over publishing the checker because there is nothing to keep in step: the check always uses
the code on workshop's main. About 15 s a run.

Per entry, everything reported, not stopping at the first:

- core's index rules for the entry;
- the pinned commit fetched exactly as install fetches it (one commit, no hooks, submodules, LFS,
  or symlinks, no global or system git config, `.git` deleted);
- `tile check` as an outside tile;
- `id`, `version` and `permissions` exactly tile.json's (permissions compared as JSON, so what the
  menu shows before install is what runs);
- the entry page and every relative `src` / `href` in it are in the commit (nothing is built on
  install); a package.json with install scripts is a warning (never run);
- `transcripts` with `net`, on either side, fails with "a maintainer reads the code and adds the
  reviewed label"; the label (created) lets it through on the next run.

A tile whose `workshop` range starts above core main's bridge is "waiting", not failed, when its
only errors are the range and permissions core does not know. A permission core does not know in
a tile that does not ask for a newer core fails (a typo).

The summary (`$GITHUB_STEP_SUMMARY`) is a table: status, tile, commit, what it can do in words,
and against the base branch: new, `0.1.0 → 0.2.0; now also: …`, or removed. Also runs on push to
main, by hand, and Mondays (an entry a newer core would refuse shows up).

### Core

- `src/shared/tile-index.ts`: `DEFAULT_INDEX` (the raw URL of tiles.json on main) and
  `indexSource({ env, setting, smoke })`: WORKSHOP_INDEX, else settings, else the default, never
  the network in a smoke run.
- `src/main/index-read.ts` (new, no electron): `IndexReader` from tile-menu.ts's old `readIndex`.
  Node's fetch, 10 s timeout, the body counted as it streams and dropped past 2 MB whatever
  content-length says, an https answer kept 60 s (the tab used to fetch on every tile change), a
  failure never kept, and problems in words ("could not reach raw.githubusercontent.com
  (offline?)", "answered 404", "did not answer in 10 s", "it is not JSON"). A local file is read
  every time. "Read" with an address skips the cache.
- `src/main/tile-menu.ts`: uses both. Smaller.
- `src/main/install.ts`: git runs with `GIT_CONFIG_GLOBAL=/dev/null` as well as no system config.
  A user's `url."git@github.com:".insteadOf https://github.com/` would turn the https fetch into
  ssh, which has no agent in that environment. Not seen failing (Colin has no such rule); fixed
  before anyone does. Proxy variables are passed through. A tile asking for a newer bridge is
  refused with "this tile needs a newer workshop (…); update workshop, then install it".
- `src/renderer/src/TilePicker.tsx`: "Reading the index…" until it answers; the old "the index
  does not exist yet" text is now only for no index at all (a smoke run); the field's empty

- `src/main/smoke-install.ts`: `realIndex`, run by `WORKSHOP_REAL_INDEX=1` (in place of the rest

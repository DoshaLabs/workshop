| ... and a reboot | the tmux server killed, a third core started | the session is closed, resumes with `--resume <its id>`, and the conversation goes on in the same transcript |

Two things counters needed: `Knot.tsx` keeps `window.knotCounts` (`draws`, `wakes`, two integers)
for the clock checks. `index.ts` takes `--smoke-restarted` (with `WORKSHOP_SMOKE_HOME` /
`WORKSHOP_SMOKE_PROFILE`) to start on a smoke run's profile and run `runRestarted` instead of the
smoke; it leaves the tmux server for the first run to kill.

**Found and fixed: DNS prefetch was a way out of the sandbox.** A tile's `<link
rel=dns-prefetch href="https://<anything>.example.com">` (or the same in a srcdoc frame) sent that
name to the system resolver: the net log showed the DNS queries. A tile could spell data into names
under a domain whose nameserver it controls. The dead proxy does not cover prefetch. Tried and not
enough: an `X-DNS-Prefetch-Control: off` header on every tile:// response, and a `default-src
'self'` CSP (core's own window has one and still looks names up). The fix: every tile webview
starts with `additionalArguments: ['--blink-settings=dnsPrefetchingEnabled=false']`
(`index.ts`, will-attach-webview). It is per renderer, so core's window is unchanged and stays the
check's control. `preconnect` was never resolved from a tile, but the control did not resolve it
either, so that half is not proven by the check. Not covered: a cross-origin frame of a host the
tile declared would run in its own process, which may not get the switch; such a tile already has
the network to that host.

**Found and fixed: the first read of a long transcript.** It parsed every line on the main process
and let the blocks grow without limit until the end, so each tool result searched tens of
thousands of blocks for its call: 73 MB took about 420 ms. Real transcripts on this machine reach
270 MB (file sizes only were looked at, and one count of title lines). Now (`src/main/transcript.ts`)
a file over 4 MB is read from its last 4 MB, doubling until it holds the 80 blocks a tile shows,
trimmed as it goes: 8 ms. The title, when the end has none, is found by searching bytes backwards
and parsing only lines that hold `"ai-title"` (about 50 ms when it is only at the start; the real
CLI writes it again every dozen lines or so). The window gets one message for the whole file. The
test compares against reading every line in the same run, so a busy machine slows both.

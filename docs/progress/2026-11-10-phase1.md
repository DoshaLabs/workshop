## 1. Usage where it can be seen

- `UsageMeter.tsx`: the 5-hour and weekly meters are always in the top bar. Until a session has
  reported one, it is an empty bar and a dash, and its tooltip says why (a session reports after
  its first reply, and only on a subscription). Once known: the bar, the percentage, the time left;
  amber from 70%, red from 90%, said in the tooltip too. It re-reads the clock every 30 s.
- `SessionUsage`: each session's context % (quiet below 70%, then amber, red at 90% with "/compact
  or a new session soon") and its cost so far at list price, on the session's tile head and on the
  focus pane's head. Nothing until its status line has said.
- Formatting (`usageLevel`, `timeLeft`, `money`) is in `src/shared/usage.ts`; `UsageTracker` now
  has unit tests too.
- **Difference from deck:** deck shows the context badge only from 50% and shows no cost on a
  session. Here both show as soon as they are known, as the brief asked.

## 2. Session tiles

- **Main** (`src/main/transcript.ts`, from deck's): tails every OPEN session's transcript every
  400 ms. The file is `<session id>.jsonl` under `$CLAUDE_CONFIG_DIR` (or `~/.claude`)
  `/projects/*/`, found by name in every project folder, never built from the cwd (a worktree
  session writes under the worktree's folder). A session whose file has not appeared is looked for
  every 2 s, not every poll. Reads hold back a torn last line and a character split across two
  reads (deck's split a multi-byte character at a 64 KB boundary). A parked session is no longer
  tailed. 80 blocks kept per session. IPC: `core.transcript(id)`, `core.onTranscript`.
- **The parser** moved to `src/shared/transcript.ts` (pure, tested against a hand-written fixture,
  `test/fixtures/transcript/basic.jsonl`). Checked against the shape of today's CLI lines (keys
  only, no content read): it now writes `api-request-blob` lines that hold copies of messages
  (ignored, since only `user` and `assistant` lines count), and user lines it injects itself
  (a background task's `<task-notification>`, a message from another session) carry an `origin`
  whose kind is not `human`. deck would show the task notifications as your prompts; here they
  are skipped. `!cmd` shows as `! cmd`; its output is skipped.
- **Markdown** is parsed to a tree in `src/shared/markdown.ts` (unit-tested) and drawn as elements
  by `Markdown.tsx`; links are http(s) only and open in the browser. deck's clickable file paths
  wait for the preview pane.
- **The column** (`SessionColumn.tsx`): a tile per open session, three to the column's height,
  most recently active first, the rest scrolling. Head: ⌘n, the status dot exactly as before
  (`<span className={`dot ${status}`} />`, left for the mascot), name, Claude's title (from the
  transcript's `ai-title`, else the terminal's), worktree and model badges, context and cost, ×
  (park). Body: `ChatView.tsx`, prompts in Nunito, prose in Source Serif 4, tool lines in JetBrains
  Mono with ✓ / ✗ / a blinking dot; three bouncing dots while busy; a "your turn" or "waiting for
  you in the terminal" note. Foot: deck's prompt bar (⏎ sends into that session by bracketed paste
  without focusing it, ⇧⏎ a new line, Esc empties). A click (not a text selection) opens the
  session's terminal in the center.
- **The focused session** is in the center as its terminal, the only one mounted and so the only
  WebGL context any session holds; its tile gives way to a slim line ("in the center") so the
  column still says where it is. With the launcher or a tile's pane in the center, every open
  session is a tile and no terminal is mounted at all.
- **Parked sessions** are a "Closed" card at the column's foot, under a dashed + (new session);
  click to resume, ⌫ twice to end.
- `Guard.tsx`: a render error in one conversation (or the column) shows a line in its place
  instead of unmounting the window, and retries on the next transcript.
- The stand-in CLI (`test/fixtures/fake-claude/claude`) appends each turn to a transcript the way
  the real one does (prompt, a meta line, prose with markdown, a Read and its result, a subagent
  line, a title). Smoke runs give sessions their own `CLAUDE_CONFIG_DIR` in the throwaway profile.

## 3. Keyboard shortcuts

- ⌘1–9 focus a session, ⌘[ / ⌘] step (wrapping), ⌘N opens the launcher. A session reached this
  way takes the whole center (launcher, pane and overlay give way).
- Main catches them in `before-input-event` on core's window and on every tile's page
  (`coreShortcuts` in `index.ts`, registered before the tile's gesture listener so a shortcut never
  counts as a click for `openOverlay`); the page never sees them. Matching is by key or by
  physical key (`src/shared/shortcuts.ts`), ⌘ alone (with ⌃, ⌥ or ⇧ it is left to whoever wants it).
- **Decision to confirm:** the numbers follow the order sessions were STARTED (stable), not the
  column's recency order (which changes as you work), and each tile wears its ⌘n. deck had fixed
  slots; workshop dropped them, and this is the nearest stable thing.

## 4. The tile column's state in settings

- `settings.column` (`{ off, extra, spans }`, cleaned by `src/shared/column.ts`) replaces the
  window's `workshop.off`, `workshop.extra` and `workshop.span` localStorage keys. A profile with
  no column saved takes what localStorage held, once, and removes the old keys. IPC:
  `core.column()`, `core.setColumn(c)`; main queues the writes.
- No tile page is mounted until the column has arrived, so a tile that turns out to be off is
  never created and thrown away.
- `column` is left out of the cleaned settings until first saved, so `cleanSettings`'s existing
  tests (and any field the mascot branch adds beside it) are untouched.

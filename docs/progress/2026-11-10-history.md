## What the PostToolUse payload carries (Claude Code 2.1.322, seen, not from docs)

One real `claude -p --model haiku` run in a temp repo with only a PostToolUse hook (matcher
`Bash`) that saved its stdin, asked to commit a file:

```json
{ "session_id": "…", "transcript_path": "…/<id>.jsonl", "cwd": "<the repo>", "prompt_id": "…",
  "permission_mode": "default", "effort": { "level": "medium" }, "hook_event_name": "PostToolUse",
  "tool_name": "Bash",
  "tool_input": { "command": "git add b.txt && git commit -m '…'", "description": "…" },
  "tool_response": { "stdout": "[main d45a3c1] add b\n …", "stderr": "", "interrupted": false,
    "isImage": false, "noOutputExpected": false,
    "gitOperation": { "commit": { "sha": "d45a3c1", "kind": "committed", "branch": "main" } } },
  "tool_use_id": "toolu_…", "duration_ms": 459 }
```

`gitOperation` is the CLI's own reading of a commit (short sha). `duration_ms` bounds when the
call ran. `cwd` is the folder the Bash tool is in (it follows a `cd`). The fake-claude fixture now
sends exactly these fields (`bash <command>`), and honours hook matchers.

## How a commit gets its session

- **Exact** (`src/main/commits.ts`). The `--settings` file gains `PostToolUse` with matcher
  `Bash`, posting to `/hook/tool` with the session's token like every other hook. It runs after
  every Bash call, so the shell first checks whether the payload mentions `git` at all
  (`case "$p" in *git*)`) and posts nothing otherwise; `curl -m 2`, output dropped, `exit 0`: it
  never blocks or fails a call. The door's hook routes now take bodies up to 1 MB (a payload holds
  the call's output; the CLI caps that near 30,000 characters). Core checks the payload names the
  token's own session (as for every hook), then acts only when `tool_response.gitOperation.commit`
  is there or the command runs `git commit | merge | cherry-pick | rebase | revert | am | pull`
  (global options such as `-C dir`, `-c k=v`, `--no-pager` allowed before it; `commit-tree`, `log
  --grep commit` and the like are not). It reads HEAD's reflog (`git log -g`, last 100 moves) in
  the call's `cwd` and in folders the command names with `git -C <dir>` or `cd <dir>` (four at
  most, no `~` or `$`), and takes the entries **from the second the call started**
  (`now − duration_ms`, floored to the reflog's whole seconds) to a second after it ended, whose
  message says a commit was made there: `commit` (initial, amend, merge), a merge that made a merge
  commit, `cherry-pick`, `revert`, `rebase … (pick | continue | squash | fixup | reword | edit)`,
  `am`, a pull that merged. Not a fast-forward (those commits were made elsewhere), a checkout, a
  reset, or a rebase's start or finish. The CLI's `gitOperation` sha is resolved in `cwd` and
  added. Each sha is recorded once: the first session to claim it keeps it.
- **The store**: `<profile>/commits.json`, `{ format: 1, commits: [[sha, session id, session
  name, recorded at], …] }`. Nothing else: never the command (it can hold a token), its output or
  a folder. Read once at start; a broken file is dropped with a warning (these are tags, not
  work). Written atomically (a temp file, mode 0600, renamed over it), one write at a time.
  **Pruned** at start and on every add: records older than 90 days go, then the oldest past
  5,000. A store that size is about 400 KB; it is sent whole to the backend when it changes,
  which is only when a session commits.
- **Probable** (`tiles/git/lib/log.mjs` `attribute`). For a commit with no record: the sessions
  whose worktree's HEAD reaches it (on the branch checked out there, walking parents among the
  commits read) and whose lifetime holds its commit time (from `started` to now, or to `active`
  if the session is dead). If several fit, sessions away from main win (main's worktree reaches
  every merged commit). One left: "probably wt-feat"; several: "probably a or b". Every session
  core knows in the project counts, parked ones too (their commits are still theirs); a session
  that was killed is gone from core's list, so its unrecorded commits are untagged.
- **Untagged**: everything else.

Commit time (`%ct`), not author time, is used for the lifetime, "Today" and the row's "ago": a
rebase or cherry-pick keeps the old author date, but the commit was made now.

## The tab

- **Backend ops** (`tiles/git/backend.mjs`, `lib/history.mjs`): `history` `{ sessions, limit }` →
  per project of those sessions `{ root, name, commits, more }`; each commit `{ sha, parents,
  author, at, ct, refs: [{ name, kind: head | branch | tag | remote }], subject (300 chars), by:
  { kind: exact | probable, ids, names } | null }`. The log is `git log --exclude=refs/stash --all
  --date-order -z --decorate=full` with the format `%H %P %an %at %ct %D %s` split by 0x1f, one
  more than the limit to know if there is more; 300 at first, "Show 300 more" up to 3,000. A
  repository with no commits is an empty log. `commit` `{ root, sha }` → `git show --format=
  --diff-merges=first-parent` with the Changes tab's diff flags and caps, parsed by `parseDiff`
  (a merge shows what it brought to its branch; the first commit shows all added). The root must
  be a session's, the sha a full 40 or 64 hex, and `cat-file -t` must say commit. The records are
  never sent to the page: only each commit's `by`.
- **Rows**: subject, short sha; the tag (exact: the name on an accent tint; a guess: "probably …"
  in muted italics in a dashed box, with a tooltip saying it is a guess and not recorded), `merge`,
  the refs (the checked-out branch first, in the accent), and "5 min ago" (title: the date and
  the author). A click unfolds the diff with the Changes renderer (files fold too); it is fetched
  once per commit.
- **Today, by session** (filter beside All): the last 24 hours by commit time across every
  project, one group per session (its dot, name, "3 commits, 1 a guess"), newest group first;
  then "Not sure which session" (a guess between several) and "No session" per project. Inside a
  session's group an exact tag would repeat the heading, so only guesses are labelled there.
- **Live**: a poll every 8 s while the tab is up and the page visible; at once when a session
  opens, closes or changes status; and at once when core records a commit: the backend gets the
  new records and emits `commits`, which reaches the page as `workshop.backend.onEvent`. A poll
  that changed nothing draws nothing.
- The "null" before "live" in the tile's bar: `replaceChildren` drew a left-out filter as the
  word "null" (on Changes and History; Worktrees had its filter there). The bar now goes through
  `shown()` in model.js, and the head's badge through `badgeOf()` (nothing before the first answer
  or when clean); `test/git-page.test.ts` covers both and the smoke checks the bar's text.

## Track B changes

`BackendSession` gains `started` and `active`; a `commits` message to backends (`kit.commits()`,
`kit.onCommits`); an `event` message from them (`kit.emit(name, data)`, 64 KB, name checked)
passed to the tile's pages as `workshop.backend.onEvent(fn)` (`CH.backendEvent`). Written up in
`2026-11-10-track-b.md`.

## Not done, or not verified

- **The same second.** The reflog keeps whole seconds, so a commit someone else made in the very
  second a session's committing call started would be recorded as the session's. The smoke had to
  space its own commit a second from the session's next one. A PreToolUse hook noting HEAD before
  each call would close it, at the cost of a second hook on every Bash call; not done.
- A commit made by a script the command runs in another folder, not named by `-C` or `cd`, is
  missed (unless the CLI's `gitOperation` names it and it resolves in `cwd`). A commit made by a
  subagent's Bash call: whether PostToolUse fires for subagent tool calls, and with which
  `session_id`, was not checked; if it carries the parent's id it is recorded as the parent's.
- One real run was done to read the payload; the whole path (real CLI → hook → core → tile) was
  run only with fake-claude.
- `gh pr merge`, `git commit` through an alias or a GUI, and the Worktrees tab's own merge or
  rebase are not recorded (no Bash call by a session): they are guessed or untagged.
- Reachability for the guess is walked only among the commits read (300 by default): a session
  whose worktree's HEAD is older than the page is not matched.
- Very large repositories: `git log -n 301 --all` is fast; not measured past a few thousand refs.

## Decisions for Colin

1. Exact attribution from PostToolUse on Bash plus HEAD's reflog in the call's window, taking the
   CLI's own `gitOperation` sha as well. The list of committing subcommands: commit, merge,
   cherry-pick, rebase, revert, am, pull.
2. The hook posts only payloads mentioning "git" (a shell `case`), to keep the cost of every
   other Bash call at one `sh`.
3. Store: 90 days, 5,000 records, shas + session id + name + time only.
4. A guess needs the worktree's branch to reach the commit and the session's lifetime to hold its
   commit time; a session off main beats one on main; several left are all named.
5. Commit time, not author time, for "Today" and the guesses.
6. The filter reads "Today, by session" (no "Claude"); a guess inside its own session's group still
   says "probably".
7. A backend → page event (`emit` / `onEvent`) rather than a faster poll.

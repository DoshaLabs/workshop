# Progress: 10 Nov 2026, the first build session

One long Claude Code session took workshop from a plan (`CLAUDE.md`, commit `0776d24`) to a
working app: the tile host (roadmap step 1), most of the tile contract, themes, and sessions (the
start of step 3). This file records what was built, how it was checked, what went wrong on the
way, and what a second pass over the codebase should look at. Read it with `CLAUDE.md`, whose
"What exists" section is the short version.

Everything here is on `main` and pushed to `DoshaLabs/workshop` (private), up to `16ef655`.

## 3. Bugs and trouble along the way (all fixed unless marked)

1. **A sandboxed preload must be one file.** electron-vite split the two preloads into a shared
   chunk the sandboxed tile preload cannot `require`, so `window.workshop` never appeared.
   electron-vite's `isolatedEntries` fixes that but crashes when stdout is not a TTY
   (`process.stdout.clearLine is not a function`). Fix: the tile preload has its own build,
   `vite.tile-preload.config.ts`, run by `npm run build`.
2. **`contextBridge` copies a getter's value once**, so `workshop.view` never changed. Fix: live
   values cross as functions and `contextBridge.executeInMainWorld` rebuilds them into getters in
   the page's world. That API is marked **experimental** in Electron 44: watch it on upgrades.
3. **A blocked navigation wiped the tile's door ops**: `did-start-navigation` fires even when
   `will-navigate` is prevented. Fix: ops reset when a new document says hello.
4. **Wikimedia now serves thumbnails from `thumb.wikimedia.org`** as well as
   `upload.wikimedia.org`; the Wikipedia tile declares both.
5. **`executeJavaScript` cannot return a function** ("An object could not be cloned"): a smoke
   test returned `onViewChange`'s unsubscribe.
6. **Every smoke run opened example.com in Colin's browser, twice.** The probe's popup and
   navigation tests were refused and then handed to the real browser, as tile links are meant to
   be. Fix: smoke runs record instead of opening (`e4fe4e6`), and the hand-off is rate limited.
7. **Core's window cannot `location.reload()`**: its `will-navigate` guard blocks it. The smoke
   test reloads from main. **See open issue A below: this probably breaks `npm run dev`.**
8. **On a window reload the old webviews are not gone before the new ones attach.** Refusing a
   second page for an instance blocked the reload; now a new page replaces the old one. **See open
   issue B: the old page's teardown can still fail the new page's door calls.**
9. **Gated bridge methods threw synchronously** when a permission was missing, so `.then/.catch`
   never saw the error. They reject now.
10. **`tmux kill-server` left its socket file** in `/tmp/tmux-<uid>/`. Core removes it.
11. **Terminal looked wrong**: xterm's stylesheet painted the viewport black, the native scrollbar
    was light under a dark theme, and the head showed the host name (tmux's default pane title).
    Fixed: clear viewport, `color-scheme` from the theme (core's window and every tile, via
    `--ws-scheme`), host-name titles ignored.
12. **A tile in the center pane hid a session just started.** A session coming into focus now
    takes the center back.
13. **Tooling, not code:** auto mode refused the very first heredoc that wrote several files at once
    ("Irreversible Local Destruction"); writing files with the editor tool worked.

## 4. Open issues, found but not fixed

**A. FIXED (second session, section 8).** ~~`npm run dev` is untested, and likely broken in one way.~~ Every check ran a production
build (`electron .`). Core's window prevents all navigation (`src/main/index.ts:444`), which also
stops Vite's full-page reload under `npm run dev`. Allow navigation to `ELECTRON_RENDERER_URL` (and
reloads) in dev, then run `npm run dev` by hand.

**B. FIXED (second session, section 8).** ~~A replaced page drops its successor's door calls.~~ When an instance's old page is destroyed
after its replacement attached, `door.dropInstance(key)` (`src/main/index.ts:222`) fails every
pending call for that key, including ones delivered to the new page. Only drop when
`liveByTile.get(key) === g`, or track pending calls per webContents.
A second half, found 11 Nov 2026 (smoke's "a reloaded page has what it kept" failed about 1 run in
8, on main too): a page reloaded in place (`wc.reload()`, a dev tile saved) keeps its webContents,
so it was the same page to the door, its old ops still listed; a call landing as the old document
unloaded was lost and waited out the tile's timeout. Now a page is `key@wc#doc`, and when a new
document commits (`did-navigate`; not at the start, since a navigation the sandbox cancels leaves
the page as it was) its ops are cleared and the old document's pending calls fail at once.

**C. Packaging does not exist, and paths assume an unpacked app.** `tmux.conf`,
`bin/workshop-tile.mjs` and `tiles/` are read from `app.getAppPath()`; in a packaged build that is
inside an asar archive, where tmux and node cannot read them. deck ships these as
`extraResources`. No electron-builder config, icon, entitlements or install script yet.

**D. Not exercised by any test:**
- The real fleet poll (`claude agents --json` every 1.5 s): smoke turns it off.
- Sessions surviving an app restart (quit, relaunch, reattach, tokens re-registered, hooks finding
  the port file), and a reboot (tmux gone → `--resume`).
- The WebRTC and DNS-prefetch side doors the dead proxy is meant to close: argued, not tested.
- Camera and microphone permissions: the handler exists, nothing calls it.
- Anything done by a person with a mouse and keyboard: launcher, theme picker, column buttons,
  drag, Esc, focus.

**E. Smaller things to look at:**
- Tile column state (`off`, `extra` instances) lives in the window's `localStorage`, not in core's
  settings.
- `MAX_INSTANCES` is defined twice (`src/main/tiles.ts` and `src/renderer/src/App.tsx`).
- `storage.watch` also fires for the page that wrote the value.
- `notify({ bark })` is accepted and ignored (no mascot yet).
- A tile's head title survives a reload of its page.
- The door answers 503 while a tile is still registering its ops at start-up; callers must retry.
- `door.json` lets any process of the user call any tile as "outside". By design, but worth a line
  in the docs.
- The dead proxy is `127.0.0.1:9`: anything listening there locally would receive the CONNECTs.
- File grants can only be forgotten by the tile (`files.forget`); the user has no list to revoke
  from.
- The status-line script captures the user's own status-line command when it is written (each
  launch); a change to theirs needs a relaunch. Claude Code's theme applies to new sessions only.
- `cosmos.ts` animates two canvases at 30 fps whenever Deep Space is on: measure its CPU cost.
- Glass is a solid theme until deck's picture wall comes over.
- No keyboard shortcuts (deck has ⌘1–9, ⌘[ ⌘], ⌘N …).
- Repo hygiene: no `LICENSE` file (MIT is stated; copyright holder to decide) and no `README`.
  `claude plugin validate` flags both for the Wikipedia tile's plugin.

## 6. Decisions made in this session (confirm or reverse)

- The tile's Claude Code half is a folder named `plugin/` (Colin asked for "the plugin layout for
  the skill/ folder"; the folder was renamed because it is now a whole plugin).
- A tile plugin may hold **skills only**: hooks, MCP servers, agents and commands run with a
  session's full permissions, so they wait for the trusted tier.
- `net` is https / wss only, host names only (no IPs, no `localhost`, no bare `*`); `*.x.com`
  does not include `x.com`.
- Unknown permissions in `tile.json` are an error, not a warning.
- Session tokens live in 0600 files named by `WORKSHOP_AUTH`, never on a command line; the door's
  caller is the session's name; a hook naming another session's id is ignored.
- Tiles see sessions without titles (titles quote the conversation).
- `sessions.paste` is rate limited to one every two seconds per tile, 10,000 characters at most.
- Profiles: `workshop` and `workshop-dev` (its own tmux socket and data folder).
- Deep Space is the default theme.
- Models in the launcher are aliases only (Fable, Opus, Sonnet, Haiku, Opus plan, the 1M
  variants); deck's pinned legacy Opus 4.6 was dropped.

## 8. Second session, same day: issues A and B, thirds, and the Reminders port

Not committed when this was written. `npm test` 73 passing, `npm run smoke` 106 passing.

### Fixed

- **A, `npm run dev`.** Two faults, not one. Core's window refused Vite's reload (now a navigation
  to the dev server's own origin is let through, in dev only). And `electron-vite dev` emptied
  `out/preload`, deleting the `tile.js` that `npm run dev` had just built, so under dev no tile had
  `window.workshop` at all (`electron.vite.config.ts`: `emptyOutDir: false`). Checked by hand:
  `npm run dev`, a window reload and a Vite reload, the door answering after each.
- **B.** The door tracks a pending call by the PAGE it went to (`<instance>@<webContents id>`),
  not the instance, so an old page going away fails only its own calls (`Door.dropPage`).
- **Columns are thirds**, as in deck (`styles.css`, `.app`). deck's narrow-window rule (below
  1400 px the tile column goes) was not carried over.

### The Reminders tile (`tiles/reminders/`)

deck's tile, feature for feature except where noted: three tabs (to do, notes, log), by project,
priorities, due dates, detail, armed delete, completed reminders swept at the day's end, ten door
ops, a skill. Plain JS, no build, about 900 lines against deck's 1,030 across main, renderer and
CLI. The state is one key in `workshop.storage`.

### What the port found in the contract

1. **A door call could not say which session made it.** `caller` is the session's name, and names
   are not unique (two "new session"s). Reminders files an item under the caller's folder, so it
   needs the session. Added: a call carries the session's id, `fn(args, caller, { session })`,
   matched against `workshop.sessions`. Decision to confirm.
2. **A sandboxed tile cannot resolve a folder.** deck ran `git rev-parse --show-toplevel` so a
   subfolder or a worktree counted as its repo, and expanded `~` and relative paths. The tile can
   do none of that. Here a project is the session's start folder as core reports it, an absolute
   path, or the folder name of a project the tile already knows. If "project" should mean the
   repo root, core should resolve it once and report it in `workshop.sessions`.
3. **No way to pick a folder and learn its path** (`files.pick` hides the path by design). deck's
   "Choose a folder…" became a typed absolute path. Fine for this tile.
4. **`workshop.storage` starts empty on a store it cannot parse**, and the next write replaces the
   file (`storage.ts` `load`). deck moved an unreadable file aside. Not fixed.
5. **The door hands a tile strings only**, so each tile parses its own flags (`model.js`
   `parseCall`). Workable, but every tile with options will write this again: a candidate for the
   tile template.
6. **A notify chip lasts 8 s and then is gone**; there is no "needs you" state that stays.
7. Nothing imports deck's existing `reminders.json`. The `files` permission could do it.

### The Wikipedia tile (`tiles/wikipedia/`)

deck's `WikiTile.tsx` and `Weather.tsx` (and the fetching in `wiki.ts` / `weather.ts`, which ran
in deck's main) replace the small reference tile. Plain JS, no build: `dist/wiki.js` holds the
rules (URLs, the feeds' answers, the cycle order, WMO codes, places), `test/wikipedia.test.ts`
runs it as shipped. The three door ops are unchanged. `npm test` 83, `npm run smoke` 113.

- **Kept from deck:** the picture full bleed, ‹ › and the 2-minute cycle (today, two from the
  archive, today), the clock ticking each second, the weather strip (first place large, others a
  line each with their own time when it differs), the places editor (↑, ×, °F / °C, geocoder
  search with "name, region" ranking), search with a debounce, the article in place.
- **Changed:** first run asks for a city instead of defaulting to Portland, Maine; "not now"
  saves an empty list so it does not ask again. The unit defaults from the locale. deck's
  full-window viewer became the pane: a click on the picture opens the tile as a pane, where the
  picture is shown whole with its caption and a Commons link on the theme's panel; Esc closes it.
  Colours not over the picture come from `--ws-*`.
- **Left out:** "use as wallpaper" (a tile cannot set core's wall, and Glass is solid for now),
  and the last article being reopened on start (deck never did it).
- **Contract:** nothing missing. A tile cannot portal outside its own webview, so a "look at it
  large" overlay over the whole window is not possible; the pane covers it. A tile cannot set a
  User-Agent, so Wikimedia sees Chromium's, not a named client.

### The + menu, tile heights, and making a tile with Claude

- **The `+` is the last cell of the tile column**, as in deck. Its menu opens in its place (a card
  in the column, because nothing core draws can sit over a tile's webview): tiles that are off,
  "another" for a `multiple` tile, and "make one with Claude".
- **Tile heights follow deck's default**: the column is four rows, a tile is one row, ↕ steps it
  1 → 4 → 1 (kept per instance in the window's `localStorage`, like `off` and `extra`). The
  Wikipedia and Reminders manifests now say `span: 1`.
- **Make one with Claude**: a name and an idea → `template/` copied to `~/workshop-tiles/<id>`,
  loaded as a dev tile at once, and a session started in that folder with the idea as its first
  prompt. The folder's `CLAUDE.md` is the contract, so the session needs no plugin.
- **Dev tiles are remembered** (`settings.devTiles`); "stop loading" in the menu forgets one.

Open, on the path a tile author walks:
- No `workshop tile check <folder>`: a refused `tile.json` is only reported in the window's
  center pane, which the Claude building the tile cannot see.
- No install: nothing copies a finished tile into userData `tiles/`, and there is no template
  repo, `npm create` script or index yet. A made tile stays a dev tile.
- A new folder meets Claude Code's "trust this folder?" question before the first prompt runs.
- Core's own tiles (Wikipedia, Reminders) were written in `tiles/`, not through this path.

### The overlay view, and Wikipedia's lightbox back

Colin did not accept the pane as the picture viewer, so the contract grew a third view (bridge
1.1.0). `permissions.overlay: true` lets a tile call `workshop.openOverlay()`: core lays the
tile's own webview (never remounted) over the window below a 40 px strip that core draws (icon,
name, Esc, ×), and tells the page `view === 'overlay'`. The Wikipedia tile draws deck's Viewer in
it: the picture uncropped at 70vw, tag, title, credit, ‹ ›, the Commons link, a × and a click
outside to close; the 2-minute cycle waits while it is open. The head's ⤢ still opens the pane.

- **The way out is core's.** Main takes Esc in `before-input-event` on every webContents (core's
  window and every tile) while an overlay is up, so the page never sees it; the strip sits outside
  the webview. Opening needs a mouse-down, tap or key (not Esc) that reached the page through
  Chromium's input (`input-event`), in the last 5 s, used up by the open and by leaving the
  overlay: a script, `executeJavaScript(…, true)` or a timer cannot open it, nor can a page reopen
  itself the moment it is closed. Main refuses `setView('overlay')` for a tile without the permission.
- **Still spoofable:** below the strip the page owns the whole window and may draw a fake session
  column, fake prompts or a fake ×. The strip naming the tile is the defence; it says the author for
  tiles not shipped with core. Any click or key in a tile is enough to open it, as with a browser's
  fullscreen. While open, the window's drag region is only the strip.
- **Differences from deck:** no backdrop blur (a page's `backdrop-filter` cannot see the window
  behind the webview), and deck's Viewer had no ‹ › (added here, as asked). The dim is the page's
  own `--ws-bg` at 70%.
- Smoke: 12 new checks (refused without a click, script clicks do not count, a real click opens
  it, it covers the window below the strip, the picture loads large and whole, Esc from inside
  closes it unseen by the page, the opening click cannot reopen it, strip ×, Esc from core's
  window, click outside) and the probe's `openOverlay` is refused. `WORKSHOP_SHOT_OVERLAY=x.png`
  saves the window with the lightbox open.

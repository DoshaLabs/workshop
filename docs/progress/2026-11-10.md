# Progress: 10 Nov 2026, the first build session

One long Claude Code session took workshop from a plan (`CLAUDE.md`, commit `0776d24`) to a
working app: the tile host (roadmap step 1), most of the tile contract, themes, and sessions (the
start of step 3). This file records what was built, how it was checked, what went wrong on the
way, and what a second pass over the codebase should look at. Read it with `CLAUDE.md`, whose
"What exists" section is the short version.

Everything here is on `main` and pushed to `DoshaLabs/workshop` (private), up to `16ef655`.

## 2. How it was checked

- `npm test`: 65 unit tests (manifest, net rule, dev entries, storage, door, plugin, files, settings).
- `npm run typecheck`: clean.
- `npm run smoke`: 93 checks, all passing at `16ef655`. It starts the real app with a throwaway

  the real CLI accepted our `--settings` file, its UserPromptSubmit / Stop hooks and status line
  reached core with the session's token, and it answered.

  the layout was looked at. **No human has clicked through the app yet.**

  it the probe, `workshop-tile probe echo hello` answered. (That run created
  `~/Library/Application Support/workshop` on Colin's machine.)

## 3. Bugs and trouble along the way (all fixed unless marked)

1. **A sandboxed preload must be one file.** electron-vite split the two preloads into a shared
   chunk the sandboxed tile preload cannot `require`, so `window.workshop` never appeared.
   electron-vite's `isolatedEntries` fixes that but crashes when stdout is not a TTY
   (`process.stdout.clearLine is not a function`). Fix: the tile preload has its own build,
   `vite.tile-preload.config.ts`, run by `npm run build`.
2. **`contextBridge` copies a getter's value once**, so `workshop.view` never changed. Fix: live
   values cross as functions and `contextBridge.executeInMainWorld` rebuilds them into getters in
   the page's world. That API is marked **experimental** in Electron 44: watch it on upgrades.
3. **A blocked navigation wiped the tile's door ops**: `did-start-navigation` fires even when
   `will-navigate` is prevented. Fix: ops reset when a new document says hello.
4. **Wikimedia now serves thumbnails from `thumb.wikimedia.org`** as well as
   `upload.wikimedia.org`; the Wikipedia tile declares both.
5. **`executeJavaScript` cannot return a function** ("An object could not be cloned"): a smoke
   test returned `onViewChange`'s unsubscribe.
6. **Every smoke run opened example.com in Colin's browser, twice.** The probe's popup and
   navigation tests were refused and then handed to the real browser, as tile links are meant to
   be. Fix: smoke runs record instead of opening (`e4fe4e6`), and the hand-off is rate limited.
7. **Core's window cannot `location.reload()`**: its `will-navigate` guard blocks it. The smoke
   test reloads from main. **See open issue A below: this probably breaks `npm run dev`.**
8. **On a window reload the old webviews are not gone before the new ones attach.** Refusing a
   second page for an instance blocked the reload; now a new page replaces the old one. **See open
   issue B: the old page's teardown can still fail the new page's door calls.**
9. **Gated bridge methods threw synchronously** when a permission was missing, so `.then/.catch`
   never saw the error. They reject now.
10. **`tmux kill-server` left its socket file** in `/tmp/tmux-<uid>/`. Core removes it.
11. **Terminal looked wrong**: xterm's stylesheet painted the viewport black, the native scrollbar
    was light under a dark theme, and the head showed the host name (tmux's default pane title).
    Fixed: clear viewport, `color-scheme` from the theme (core's window and every tile, via
    `--ws-scheme`), host-name titles ignored.
12. **A tile in the center pane hid a session just started.** A session coming into focus now
    takes the center back.
13. **Tooling, not code:** auto mode refused the very first heredoc that wrote several files at once
    ("Irreversible Local Destruction"); writing files with the editor tool worked.

## 4. Open issues, found but not fixed

**A. `npm run dev` is untested, and likely broken in one way.** Every check ran a production
build (`electron .`). Core's window prevents all navigation (`src/main/index.ts:444`), which also
stops Vite's full-page reload under `npm run dev`. Allow navigation to `ELECTRON_RENDERER_URL` (and
reloads) in dev, then run `npm run dev` by hand.

**B. A replaced page drops its successor's door calls.** When an instance's old page is destroyed
after its replacement attached, `door.dropInstance(key)` (`src/main/index.ts:222`) fails every
pending call for that key, including ones delivered to the new page. Only drop when
`liveByTile.get(key) === g`, or track pending calls per webContents.

**C. Packaging does not exist, and paths assume an unpacked app.** `tmux.conf`,
`bin/workshop-tile.mjs` and `tiles/` are read from `app.getAppPath()`; in a packaged build that is
inside an asar archive, where tmux and node cannot read them. deck ships these as
`extraResources`. No electron-builder config, icon, entitlements or install script yet.

**D. Not exercised by any test:**
- The real fleet poll (`claude agents --json` every 1.5 s): smoke turns it off.
- Sessions surviving an app restart (quit, relaunch, reattach, tokens re-registered, hooks finding
  the port file), and a reboot (tmux gone → `--resume`).
- The WebRTC and DNS-prefetch side doors the dead proxy is meant to close: argued, not tested.
- Camera and microphone permissions: the handler exists, nothing calls it.
- Anything done by a person with a mouse and keyboard: launcher, theme picker, column buttons,
  drag, Esc, focus.

**E. Smaller things to look at:**
- Tile column state (`off`, `extra` instances) lives in the window's `localStorage`, not in core's
  settings.
- `MAX_INSTANCES` is defined twice (`src/main/tiles.ts` and `src/renderer/src/App.tsx`).
- `storage.watch` also fires for the page that wrote the value.
- `notify({ bark })` is accepted and ignored (no mascot yet).
- A tile's head title survives a reload of its page.
- The door answers 503 while a tile is still registering its ops at start-up; callers must retry.
- `door.json` lets any process of the user call any tile as "outside". By design, but worth a line
  in the docs.
- The dead proxy is `127.0.0.1:9`: anything listening there locally would receive the CONNECTs.
- File grants can only be forgotten by the tile (`files.forget`); the user has no list to revoke
  from.
- The status-line script captures the user's own status-line command when it is written (each
  launch); a change to theirs needs a relaunch. Claude Code's theme applies to new sessions only.
- `cosmos.ts` animates two canvases at 30 fps whenever Deep Space is on: measure its CPU cost.
- Glass is a solid theme until deck's picture wall comes over.
- No keyboard shortcuts (deck has ⌘1–9, ⌘[ ⌘], ⌘N …).
- Repo hygiene: no `LICENSE` file (MIT is stated; copyright holder to decide) and no `README`.
  `claude plugin validate` flags both for the Wikipedia tile's plugin.

## 5. A second pass over the codebase: where to look

1. **`src/main/index.ts` (526 lines)** has grown into the tile host, the bridge, dev tiles and
   startup at once. Split the bridge handlers and the webview guard into their own modules.
2. **The security boundary**, read adversarially: `tiles.ts` (protocol handler, request filter,
   proxy, permission handlers), `index.ts` (`guestOf`, `will-attach-webview`), `preload/tile.ts`,
   `files.ts`, `door.ts`. Smoke covers what we thought of; a fresh reader should try what we did
   not.
3. **Code carried from deck** (`sessions.ts`, `hooks.ts`, `usage.ts`, `fleet.ts`, `tmux.ts`,
   `env.ts`, `themes.ts`, `cosmos.ts`, `terminals.ts`): check what was dropped (slots, wolfpack, the
   leash, file links in the terminal, the fox banner) left nothing half-wired.
4. **`src/main/smoke.ts` (423 lines)** is one long script: split by area so a failure points at
   one file.
5. **Open issues A to C** before anyone else runs the app.

## 6. Decisions made in this session (confirm or reverse)

- The tile's Claude Code half is a folder named `plugin/` (Colin asked for "the plugin layout for
  the skill/ folder"; the folder was renamed because it is now a whole plugin).
- A tile plugin may hold **skills only**: hooks, MCP servers, agents and commands run with a
  session's full permissions, so they wait for the trusted tier.
- `net` is https / wss only, host names only (no IPs, no `localhost`, no bare `*`); `*.x.com`
  does not include `x.com`.
- Unknown permissions in `tile.json` are an error, not a warning.
- Session tokens live in 0600 files named by `WORKSHOP_AUTH`, never on a command line; the door's
  caller is the session's name; a hook naming another session's id is ignored.
- Tiles see sessions without titles (titles quote the conversation).
- `sessions.paste` is rate limited to one every two seconds per tile, 10,000 characters at most.
- Profiles: `workshop` and `workshop-dev` (its own tmux socket and data folder).
- Deep Space is the default theme.
- Models in the launcher are aliases only (Fable, Opus, Sonnet, Haiku, Opus plan, the 1M
  variants); deck's pinned legacy Opus 4.6 was dropped.

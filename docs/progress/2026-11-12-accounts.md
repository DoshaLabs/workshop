# Accounts: sign in again, and more than one account (12 Nov 2026)

Colin asked how a user can reauthenticate, or use a different Claude or Codex account. Ground rule 4
holds throughout: workshop never reads, copies or proxies a CLI's credentials. It runs the CLIs' own
login commands and reads only their status commands.

## What the CLIs give us (checked on this Mac)

- **Claude Code 2.1.322**: `claude auth login` (`--claudeai` default, `--console`, `--sso`,
  `--email`), `claude auth logout`, `claude auth status --json`. Status has no secret in it:
  `loggedIn`, `authMethod` (`claude.ai`, `none`…), `email`, `orgName`, `subscriptionType` (`max`),
  `planTier` (`max_20x`), `loginExpiresAt` (ISO, or null), `configDirectory`, `projectsDirectory`.
  Exit 0 signed in, 1 not.
- **Codex**: `codex login`, `codex logout`, `codex login status` (text: `Logged in using ChatGPT`,
  `Not logged in`; exit 0 / 1). The plan name comes with its rate limits (`planType`, already shown).
- **Separate accounts are separate config folders**: `CLAUDE_CONFIG_DIR`, `CODEX_HOME`. Checked:
  `CLAUDE_CONFIG_DIR=<empty folder> claude auth status --json` reads `loggedIn: false` while the
  default folder is signed in, and `CODEX_HOME=<empty folder> codex login status` reads `Not logged in`.

## Step 1: who is signed in, and sign in again (built 12 Nov 2026)

- `src/main/accounts.ts` runs both status commands at start, every 10 minutes and when the window
  comes forward (at most once a minute), with the user's shell env. Codex only when it is on PATH.
- The top bar's plan heads (`UsageMeter.tsx`) say who: the tooltip on "Claude" has the email and
  plan; signed out or past `loginExpiresAt`, the reset line under the name becomes **Sign in**.
- **Sign in** runs the CLI's own `claude auth login` / `codex login` in a pty in main (they open the
  browser and wait on their own localhost callback). The head says "Signing in…" and offers the
  sign-in page's link if the CLI printed one (a browser that did not open). It gives up after 10
  minutes; then status is read again. Workshop sees only the command's output text, never a token.
- Sessions already running keep the login they started with; the CLI reads it again on its own.

## The account manager (built 12 Nov 2026)

A click on a plan's name in the top bar (`✻ Claude`, `>_ Codex`, the glyphs each CLI's terminal
shows, as text: no logo file, ground rule 6) opens `src/renderer/src/Accounts.tsx` in core's
lightbox, a card per CLI:

- Who: email, organisation (`orgName`), how it signed in, plan, when the login runs out, the CLI's
  version (`claude --version`, `codex --version`, read with status).
- Every window the CLI reports, at reading size, with when it starts over; the open sessions of that
  CLI with context % and (Claude Code) cost at list prices, and their total.
- Sign in / Sign in again: Claude Code's own `--claudeai` (default), `--console` or `--sso`
  (`loginCommand`); Codex's `codex login`. Sign out: `claude auth logout` / `codex logout`
  (`logoutCommand`), two clicks; a failure keeps its last lines (`signOutError`).
- "Usage and billing ↗" opens the provider's own page (https://claude.ai/settings/usage,
  https://chatgpt.com/codex/settings/usage) in the browser. Billing, credits and plan changes stay
  there: showing them here would need the CLI's credentials.
- Left out on purpose: `codex login --with-api-key` (workshop would carry the key).

Step 2's account list, Add account and the launcher's choice belong in this lightbox.

## Step 2: more than one account (planned)

1. An account is a config folder. The default is the CLIs' own (`~/.claude`, `~/.codex`); others
   live in `<profile>/accounts/<name>/{claude,codex}`.
2. "Add account" = step 1's sign-in with that folder in the env.
3. The launcher picks the account; the session keeps it (`account` on its record); its tmux command
   and Codex app-server start with `CLAUDE_CONFIG_DIR` / `CODEX_HOME`; resume uses the same.
4. Knock-ons: transcripts are found under the session's own account folder (`projectsDirectory`);
   usage windows are per account (the meters follow the focused session's account, or one group per
   account); a fresh folder has none of the user's `settings.json`, `CLAUDE.md`, skills or MCP
   servers, so workshop offers to link those (settings only, never credentials); Codex's
   `config.toml` likewise.

To verify first, each with a throwaway folder and no real login: that a second `CLAUDE_CONFIG_DIR`
gets its own Keychain item on macOS; that `--resume` finds a conversation in a non-default folder;
where Codex keeps its login under `CODEX_HOME`.
